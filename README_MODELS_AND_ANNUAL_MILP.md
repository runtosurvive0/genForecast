# 예측모델과 연간 석탄 발전량 산정 원리

GenForecast의 Python 연간 계획은 **총수요와 태양광 전망 → 원전 정비 반영 → 전국 석탄 목표 예측 → 호기별 MILP 배분 → 일·월·연간 집계** 순서로 동작한다. 예측모델은 필요한 석탄 발전량의 형상을 만들고, MILP는 그 목표를 실제 호기 제약과 비용에 맞춰 배분한다. MILP가 전력수요를 학습하거나 모든 발전원의 전력시장 급전을 재현하는 구조는 아니다.

이 문서는 `codex/milp-down-reserve-improvements`의 Python 연간 실행 경로를 설명한다. 브라우저의 합성 데모·재학습 화면이나 원천 national-solar-forecast의 단기 기상예보 모델과는 다른 경로다. [설치 안내](backend/README.md), [하향 여유 이식 범위](docs/MILP_DOWN_RESERVE_PORT.md), [데이터 계약](docs/DATA_DICTIONARY.md)을 함께 참고한다.

## 1. 한눈에 보는 계산 흐름

```text
과거 시간별 발전원 구성·태양광·기온 + 공휴일 달력
  ├─ 총수요 LightGBM + 수준/성장 보정 ────────── 총수요 D(t)
  └─ 과거 태양광 형상 + 성장 보정 ──────────── 태양광 S(t)
                                                   │
원전 마스터 + 원전 정비 ── 원전 N(t)                 │
                         └─────┬───────────────────┘
                    석탄 기준량 + 잔차 LightGBM
                               │
                월별 보정 + 정비 제외 가용상한 97%
                               │
                       석탄 목표 T(t)
                               │
호기 특성·정비·월별 단가 ────────┤
상·하향 정적 여유 요구 ─────────┤
                  48시간/24시간 롤링 MILP
                    실현가능성 → 비용 초기해/비용 최소화
                               │
                   호기별 출력 P(t,j), ON/OFF
                               │
                 전국/당진 일·월·연간 MWh, 연료비
                               │
                저장된 발전계획 → 별도 연료·재고 엔진
```

| 구성 요소 | 방식 | 학습/구성 대상 | 결과 |
|---|---|---|---|
| 총수요 | LightGBM 회귀 + 외부 성장 보정 | 달력·관측 기온과 시간별 총수요 | 시간별 MW |
| 태양광 | 과거 형상 평균 또는 기준연도 재생 + 성장률 | 과거 시간별 태양광 패턴 | 시간별 MW; 별도 ML 모델 아님 |
| 석탄 목표 | 경험적 담당비율 + LightGBM 잔차 회귀 | 순수요·원전·달력과 실제 전국 석탄 출력 | 전국 석탄 목표 MW |
| 원전 | 호기 마스터·정비 규칙 | 학습모델 아님 | 원전 합계 MW |
| 석탄 가용용량 | 석탄 호기 최대출력·정비·폐지일 | 학습모델 아님 | 시간별 가용 MW |
| 호기 배분 | 혼합정수선형계획, public HiGHS | 학습 없음; 제약·비용으로 최적화 | 호기별 MW·기동·정지·부족량 |

## 2. 학습 데이터와 단위

원천 정의와 스냅샷 생성은 [history.py](backend/src/midterm/history.py)에 있다. 연간 예측은 저장된 스냅샷과 모델을 읽으며 매 실행 때 원천 DB에 접속하지 않는다.

- `demand_mw`: 5분 연료원별 출력 전체 합의 시간평균. BTM·PPA 추정 태양광도 포함한 **발전원 합계 기반 총수요 대용값**이다. 거래소 시장수요·계측 수전단 수요와 자동으로 같은 값이 되는 것은 아니다.
- `solar_mw`: 시장 태양광 + BTM 추정 + PPA 추정. `solar_market_mw`는 시장분만이다.
- `net_demand_mw = demand_mw − solar_mw`. 총태양광을 포함해 만든 총수요에서 같은 범위의 태양광을 빼며, 시장분과 총량을 섞지 않는다.
- `coal_mw`: 석탄·유연탄·국내탄의 합. `nuclear_mw`: 원자력 출력. 기온은 스냅샷의 시간별 관측소 평균이다.
- 원천 SQL은 시간당 5분 표본 10개 이상인 시간을 채택한다. 학습에서는 다시 24시간이 모두 있는 날짜만 사용한다.
- 2024-11-22 이전에는 BTM·PPA 계열이 없다. 총수요 모델 준비 단계는 겹치는 첫 90일의 `총태양광/시장태양광` 비율로 이전 총태양광을 재구성하고, `순수요+재구성 태양광`으로 총수요를 맞춘다. 이 과거 총량은 계측값이 아닌 보정값이다.

출력은 1시간 평균 MW다. 한 시간의 발전량은 `MW × 1h = MWh`, 하루는 24시간 합계다. Python 발전계획의 날짜는 KST 00~24시이며 합성 재고 데모의 09시 기준 일자와 구분한다.

공유 승인된 자료 목록·체크섬은 [shared-assets.json](backend/shared-assets.json)에 있다. 새 원천 자료·계정·접속정보·작업 DB·새 실행 결과를 이 문서 때문에 공개하거나 Git에 추가하지 않는다.

## 3. 태양광은 어떻게 전망하는가

구현: [net_demand.py](backend/src/midterm/net_demand.py)의 `_normal_solar`, `forecast_net_demand`.

### 평년기상 모드

최근 365일의 총태양광 실적에서 대상 월·일 근처 ±15일을 모아 시각별 평균 형상을 만든다. 그 형상에 기준일에서 대상일까지의 성장률을 복리로 적용한다.

```text
S(t) = 기준일 부근의 시각별 태양광 평균 × (1 + g_solar)^(기준일부터 대상일까지 일수 / 365.25)
```

이는 태양광 설비 증가에 따른 수준 변화를 반영하는 패턴 방식이다. 1년 뒤 특정 날짜의 구름·일사량을 예보하거나 태양광 물리 설비를 개별 계산하는 모델이 아니다. 평균 형상은 흐리고 맑은 날의 변동을 평탄화할 수 있다.

### 기준 기상연도 모드

예를 들어 `weather=2025`이면 2025년 같은 월·일의 기온과 태양광 실적을 함께 재생하고, 태양광에는 원천 날짜부터 대상일까지의 성장률을 곱한다. 맑고 흐린 날의 변동을 유지하지만 미래 날씨의 정답은 아니다. 해당 날짜가 없으면 오류를 내며 임의 0으로 대체하지 않는다. 2월 29일의 기상 참조는 2월 28일로 대응한다.

기본 태양광 증가율은 최근 365일과 그 이전 365일의 일평균 태양광 비율에서 구한다. 충분한 이전 표본이 없으면 코드의 기본값 15%를 사용한다. 사용자가 `solar_growth_pct`를 지정하면 그 가정이 우선한다.

별도 태양광 LightGBM·신경망을 학습하는 것이 아니므로 태양광 모델의 트리 수·학습 손실·독립 검증 정확도를 임의로 부여하지 않는다.

## 4. 전력수요 LightGBM은 어떻게 학습하는가

구현: [net_demand.py](backend/src/midterm/net_demand.py)의 `train_net_demand_model`.

학습 정답은 시간별 총수요 대용값이다. 24시간 완전 날짜를 사용하고, 하루 기온 관측이 18개 미만이면 그날을 제외한다. 나머지 기온 누락은 **그날 관측 기온 평균**으로 채운다. 학습은 관측 기온을 사용하여 냉난방 민감도를 배우며, 전망 때 평년기온 또는 기준연도 기온을 넣는다.

14개 특징은 다음과 같다.

- 시간의 sine/cosine과 시간 번호.
- 당일·전일·다음 날의 요일유형: 평일, 토요일, 일요일/공휴일.
- 설·추석 여부와 연중 위치 sine/cosine.
- 시간 기온, 일평균·최고·최저 기온, 당일과 앞 이틀의 평균 기온.

학습 설정은 L1 회귀(`regression_l1`), 600 boosting rounds, 학습률 0.05, 최대 잎 63, 잎 최소 표본 120, feature/bagging 비율 각각 0.9다. 코드는 학습 구간의 전체 표본으로 적합하며 이 함수 안에서 독립 검증 세트·early stopping을 운영하지 않는다.

트리는 관측 범위 밖의 성장 추세를 자연스럽게 외삽하지 못하므로 다음 두 보정을 별도로 적용한다.

```text
level_factor = 최근 365일 실제 총수요 합 / 같은 기간 LightGBM 예측 합
D(t) = LightGBM(달력, 기온) × level_factor × (1 + g_demand)^(수준 기준일부터 t까지 일수 / 365.25)
```

수요 증가율은 최근·이전 365일의 수준계수 비에서 추정한다. 이전 구간이 충분하지 않으면 0이다. `demand_growth_pct`로 별도 시나리오를 줄 수 있다. 평년기온은 학습 기간에서 같은 연중일 ±7일의 시각별 기온을 평균한다.

이 전망과 태양광 전망을 빼서 순수요를 만든다. **순수요 자체를 별도의 세 번째 LightGBM으로 재학습하는 구조는 아니다.**

## 5. 전국 석탄 발전량 예측모델은 어떻게 학습하는가

구현: [coal_curve.py](backend/src/midterm/coal_curve.py)의 `baseline_shares`, `training_matrix`, `train_coal_curve_model`.

먼저 실제 원전과 순수요로 원전 이후의 잔여 수요를 구한다. 요일유형별·시간별로 실제 석탄이 이 잔여 수요에서 담당했던 비율의 중앙값을 학습한다. 총 3유형×24시간의 기준 비율이다.

```text
잔여 수요 R(t) = max(총수요 D(t) − 태양광 S(t) − 원전 N(t), 0)
기준 석탄 B(t) = R(t) × 요일유형·시간별 담당비율
학습 정답 y(t) = 실제 석탄 MW − B(t)
석탄 예측 C(t) = max(B(t) + LightGBM의 잔차 보정, 0)
```

LightGBM의 11개 특징은 순수요, 원전, 순수요−원전, 기준 석탄량, 시간 sine/cosine, 당일·전일·다음 날 요일유형, 월, 명절 여부다. 과거 석탄 출력 lag를 입력으로 쓰지 않으므로 1년 전망에 오래된 ‘전일 석탄 실적’을 반복 주입하지 않는다.

학습은 최소 120개의 완전 날짜를 요구한다. 설정은 제곱오차 회귀(`regression`), 300 boosting rounds, 학습률 0.05, 최대 잎 31, 잎 최소 표본 20이다. 담당비율과 잔차 모델을 같은 제공 학습 구간에서 적합한다. 이 함수 자체에는 독립 holdout 또는 early stopping이 없다.

이 모델은 **전국 석탄 필요발전량**을 예측한다. 개별 당진 호기 출력·정지 여부나 석탄 가용용량을 직접 학습하지 않는다. LNG·수력·양수·기타 발전의 과거 분담 영향은 통계적으로 석탄 담당비율·잔차에 포함되지만, 해당 발전원들을 동시에 최적화하는 전원구성 모델은 아니다.

| 방식 | `gross-lgbm-solar-profile-v1` | `net-load-nuclear-residual-v2` |
| 학습 기간 | 2023-09-01~2026-10-03 | 2026-01-01~2026-09-29 |
| 완전 날짜 수 | 1,124일 | 271일 |
| 시간 표본 수 | 26,976행 | 6,504행 |
| 모델 파일 | [수요 메타데이터](backend/models/net-demand.json) / [트리](backend/models/net-demand.txt) | [석탄 메타데이터](backend/models/coal-curve.json) / [트리](backend/models/coal-curve.txt) |

수요 묶음의 저장 기본값은 수준계수 약 1.000586, 수요 증가율 약 +0.0933%/년, 태양광 증가율 약 +16.5919%/년, 과거 태양광 보정비 약 3.3364다. 이는 해당 학습자료에서 얻은 값이지 보편적인 연간 증가율이나 미래 확정값이 아니다.

석탄 모델의 저장 메타데이터에는 원천 프로젝트의 원전 예측 입력 설명이 남아 있다. **이 연간 실행에서는 다음 절의 호기 마스터·정비 기반 원전 경로를 사용한다.** 특징 순서·model_kind가 코드와 다르면 로더가 거부한다. `.txt`와 `.json`을 한 묶음으로 관리하며 트리 파일은 LF 줄바꿈을 유지한다.

## 6. 원전과 석탄 가용용량을 계산하는 방법

구현: [fleet.py](backend/src/midterm/fleet.py).

원전은 별도 ML 없이 활성 호기의 공급가능용량을 더하고, 정비 시간의 해당 호기를 0으로 둔 뒤 `1.003` 보정계수를 곱한다. 그 계수는 코드에 고정된 과거 경험값이다. 원전 정비 누락·지연은 석탄 목표를 크게 바꾸므로 확정 정비계획이 필요하다.

석탄 가용용량은 시간별로 `Σ(Pmax × 비정비·비폐지 여부)`다. 정비와 폐지일을 호기별 outage로 반영한다. 날짜만 입력한 정비 종료일은 그날을 포함하고 다음 날 00시부터 재가동 가능하다. 가용용량과 설치용량은 다르며, 아무 정비도 입력하지 않았다고 무정비가 검증되는 것은 아니다.

석탄 모델 원값 C(t)에 월별 보정률을 적용한 후 MILP 목표를 만든다.

```text
T(t) = clip(C(t) × (1 + 해당 월 보정률/100), 0, 0.97 × 가용 석탄 Pmax 합계)
```

97% 위의 몫을 잘랐다고 수요가 사라지거나 다른 전원이 실제로 공급했다고 증명되는 것은 아니다. 잘린 양과 목표 미달은 별도 경고·부족량으로 해석해야 한다.

## 7. MILP는 무엇을 결정하는가

구현: [uc.py](backend/src/midterm/uc.py), [headroom_uc.py](backend/src/midterm/headroom_uc.py), [highs_backend.py](backend/src/midterm/highs_backend.py).

### 결정변수와 물리 제약

- `P(t,j)`: 호기별 시간평균 출력, 연속변수.
- `u(t,j)`, `start(t,j)`, `stop(t,j)`: 운전·기동·정지 여부, 0/1 정수변수. 확률이 아니다.
- 목표 부족·초과, 상·하향 여유 부족, 하향 여유 credit·selector 등의 보조변수.

주요 제약은 `ΣP + 목표 부족 − 초과 = T`, 운전 중 Pmin/Pmax, 상·하향 출력변동률, 기동 출력 상승, 물리 최소운전·최소정지시간, 초기상태/출력/경과시간, 정비·폐지, 그룹별 운전대수 하한/상한과 동해안 MW 상한이다. 기동 중에는 코드의 시간평균 기동궤적에 따라 최소출력 하한을 완화한다.

이 연간 경로는 기존 당진 그룹 최소운전 등 연간 프로젝트의 제약을 유지한다. 원천 프로젝트의 추가 P/E 가이드·당진 rs3 유도·학습 프로필·다른 정지궤적을 일괄 복사한 것은 아니다. 추가 OFF23/OFF47 같은 최대 연속정지 제한이나 관성 벌점은 사용하지 않는다. 물리 최소정지시간은 유지한다.

### 연료비를 선형 MILP로 푸는 방법

호기 열량곡선과 월별 열량단가로 실제 평가용 2차 비용곡선을 만든다.

```text
열량 Gcal/h = heat_a2×P² + heat_a1×P + heat_a0
연료비 원/h = 월별 단가(원/Gcal) × 열량 = a×P² + b×P + c
```

연간 실행은 이 2차식을 직접 MIQP로 풀지 않는다. 최소~최대출력 사이 **할선 하나**로 선형화한다.

```text
기울기 = a×(Pmin + Pmax) + b
no-load 절편 = c − a×Pmin×Pmax
MILP 연료비 근사 = 기울기×P + no-load×u
```

절편은 음수일 수 있으며 이를 임의로 0으로 자르면 다른 비용모델이 된다. 기동·정지비도 포함한다. 결과의 연료비는 채택된 발전량에 원래 2차식을 적용해 다시 계산한다. 모델 본체의 다구간 연료 epigraph 기능과 **실제 연간 경로의 한 할선**을 혼동하지 않는다.

### 상향과 하향 여유

현재 연간 요구량은 양 방향 모두 `T(t) × scenario.reserve_ratio`다. 기본 예비율은 0.12이고 사용자가 바꿀 수 있다. 이는 원천 55일 실험의 ‘시장수요 기준 9월 p50 가을 대용 프로필’과 **다른 조건**이며 계절별 학습 프로필을 자동 선택하지 않는다.

```text
상향 여유 = Σ(정격 Pmax×u − P)
하향 여유 = Σ max(P − Pmin×u, 0)
각 부족량 = max(요구량 − 해당 여유, 0)
```

상향 주 정의는 정격 기준 프록시이며 실제 시간별 Pmax 기준 부족도 따로 진단한다. 하향은 기동 중 `P<Pmin`이면 음수가 되지 않도록 clipped 정의를 쓴다. 보조 이진 selector로 credit의 유효 상한을 묶고, 원래 최소출력 행에서 유도한 floor cut으로 탐색을 강화한다. 이는 물리 최소출력을 새로 바꾸는 제약이 아니다.

상·하향 부족의 벌점은 각각 **3,000,000원/MW·h**이고 비용단계에 추가한다. 별도 reserve 우선순위 풀이·시간분할 단계는 없다. 부족은 소프트 제약이므로 벌점 300만원을 적용해도 부족 0이 보장되지 않는다. 두 여유 모두 응답시간·램프·제어적격성을 인증한 운영 예비력이 아닌 정적 프록시다.

### HiGHS 앞단과 비용단계

연간 경로는 public `highspy==1.12.0`으로 모델을 전달하며 작업자당 solver thread는 1개다. SciPy는 희소행렬·경계·선형제약 표현과 기존 비확장 호출의 solver 인터페이스에도 사용한다. 현재 연간 확장 경로의 실제 최적화 엔진은 public HiGHS다.

1. **앞단:** 수급 목표를 정확히 맞추는 해를 먼저 찾는다. 정확해가 없고 근사를 허용하면 피크 불일치·총 불일치를 다루는 기존 앞단을 거친다. 부족/초과를 비용으로 조용히 숨기지 않는다.
2. **비용 시작해 완성:** 앞단 출력·운전 결정을 바탕으로 연료·유도·상하향 여유 보조변수를 채운다. OFF 상태의 미세한 수치 잔여출력은 selector를 켜는 근거로 쓰지 않는다.
3. **원래 모델 검사:** 전체 행·변수 경계·정수성을 원래 허용오차 `1e-5`로 검사하고 통과한 비용 시작해만 `setSolution`에 제출한다.
4. **비용 MILP:** 앞단의 수급 불일치 범위를 유지하며 연료 근사+기동/정지비+상하향 부족 벌점을 최소화한다. 앞단 조건이 충분하지 않으면 비용 풀이를 건너뛸 수 있고, 비용 해 미반환과 구분해 남긴다.
5. **반환 해 검사:** 실제 반환 incumbent도 원래 확장 모델로 검사하고, 정수 결정을 투영한 출력과 롤링 연결 물리 제약을 다시 확인한다. 유효해가 곧 예비력 충족·운영 안전 승인이라는 뜻은 아니다.

시작해 검증, 제출, `setSolution` 수락, 로그상 수락, 반환 해, 시작해 대비 비용 개선은 각각 다른 증거다. 시작해를 그대로 반환한 것을 새 경제 최적화 개선으로 표현하지 않는다. 로그 저장을 요청하지 않은 실행의 로그상 수락은 미확인으로 남는다.

연간 비용 목적은 수치 척도를 위해 전체에 0.001을 곱한다. 부족 벌점만 원 단위로 남기지 않고 모든 비용항에 같은 스케일을 적용한다. 기록된 목적함수·bound와 원래 원화 비용의 척도를 구분해야 한다.

| quality | 앞단/비용 각 호출의 기본 시간한도 | 요청 상대 gap |
|---|---:|---:|
| fast | 12초 | 0.02 = 2% |
| normal | 30초 | 0.005 = 0.5% |
| precise | 90초 | 0.001 = 0.1% |

해 미확보 시 연간 외부 재시도는 기존처럼 시간 1배/3배/6배, gap은 최초값/최소 0.01/0.05 순서다. 기존 앞단 내부 재시도·여러 단계가 있어 표의 시간은 창 전체의 총 벽시계 상한이 아니다. seed/행 검증 오류를 일반 no-plan으로 바꿔 자동 재시도하지 않는다.

gap은 벌점까지 포함한 MILP 목적함수의 incumbent과 bound 간 간격이지 실제 연료비 오차율·정지 정확도·최적해 도달 확률이 아니다.

## 8. 모든 모델을 연결해 1년을 계산하는 과정

진입점: [annual.py](backend/src/midterm/annual.py)의 `run_annual → prepare → solve_prepared`.

1. 시나리오의 시작/종료일, 기상 방식, 성장률, 12개월 석탄 보정, 예비율, 정비·열량단가·호기 마스터를 확정한다.
2. 시작일 앞에 2일 예열을 붙이고 전 기간의 시간축을 만든다. 저장된 모델로 총수요·태양광·원전·석탄 원값·보정 목표를 계산한다.
3. 전 기간 호기별 Pmin/Pmax·램프·월별 기울기/no-load·기동비·정비·폐지 및 그룹 제약을 구성한다.
4. 기간을 작업자별 독립 구간으로 나눈다. 기본 작업자 수는 CPU 수−1이며 구간 수는 대략 최소 7일당 1구간으로 제한한다. 각 구간에 다시 앞 2일을 포함한다.
5. 구간 안에서 48시간을 풀고 앞 24시간을 채택하며 다음 창으로 이동한다. 마지막 창은 남은 시간을 전부 채택한다. 이 연간 경로는 원천 날짜 실험의 고정 ‘입력50/마지막26’ 방식이 아니다.
6. 채택한 출력·운전상태·동일 상태 경과시간을 다음 창에 전달한다. 채택된 기동의 최소출력 완화 이력도 전달하고, 독립 구간 전체의 원래 물리 행을 검사한다. 부분 초기정보는 관측된 전 호기 정보로 승격하지 않는다.
7. 각 구간의 앞 48시간 예열을 버리고 해당 대상 날짜 위치에 결과를 조립한다. 겹치는 lookahead·예열 발전량을 연간 MWh나 비용에 중복 포함하지 않는다.
8. 호기별 채택 출력을 일·월·연간 합산하고 당진 호기를 별도 집계한다. 연료비는 채점 시간의 원래 2차 곡선으로 재계산한다.

```text
호기 j의 연 발전량(MWh) = Σ 대상연도 모든 시간 P(t,j) × 1h
전국 석탄 연 발전량 = Σ 모든 모형 석탄 호기의 연 발전량
당진 연 발전량 = Σ 이름/마스터가 당진인 호기의 연 발전량
기간 이용률 = 발전량 / (설비용량 × 해당 기간 전체 시간)
```

`coal_model`(ML 원값), `coal_target`(보정 목표), `coal_available`(가용설비), `Σoutput`(MILP 배분 결과)은 서로 다른 계열이다. 목표 부족·초과가 있으면 목표와 실제 반환 발전량도 다르다. 당진을 전국 석탄량의 고정 점유율로 나누지 않는다.

**독립 병렬 구간끼리의 경계는 2일 예열에 의존한다.** 구간 내 검사 통과를 연간 전체의 연속 물리 안전 인증으로 표현하지 않는다. 전체 8,760시간을 한 번에 공동 최적화하거나 구간 간 장기 운전 약속을 일관되게 최적화한 결과가 아니다.

## 9. 결과 저장과 연료수급 연결

[report.py](backend/src/midterm/report.py)의 `save_run`은 시나리오 JSON, 요약 JSON, 시간별 `hourly.npz`, 일·월 집계 Excel을 저장한다. 웹 실행은 업로드 입력 ID와 실행 상태·결과를 [milp_store.py](backend/src/midterm/milp_store.py)에서 별도 작업 DB에도 보존한다.

- 원시 `up_short_mw`, `down_short_mw`와 solver 보조 부족변수를 구분해 NPZ에 저장한다. `reserve_met`는 채택 시간의 원시 부족량으로 판단한다. 보조변수가 남는 차이를 별도 물리 부족으로 이중 집계하지 않는다.
- 모델 정보에는 요구량 기준·벌점·solver·단계별 gap/시간·시작해 검증·구간별 물리검사와 원시 부족 시간/MWh/최대 MW를 기록한다.
- 이전 실행에 새 여유 계열이 없으면 미기록이다. 새 정책의 부족량 0이나 개선 성과로 소급 해석하지 않는다.
- 수급 엔진은 저장된 호기별 발전계획을 받아 열량곡선·발열량·입하·이탄으로 소비량과 재고를 계산한다. 조회 화면을 열 때 연간 MILP를 자동으로 다시 풀지 않는다. 재고 부족을 이유로 저장된 발전계획을 조용히 재작성하지 않는다.

## 10. 학습·실행 명령과 재현 범위

아래는 로컬 전용 안내이며 명령을 실행하면 학습 모델 또는 새 계산 결과가 만들어진다. 서버 배포·공용 DB 변경과는 별도다. Python 환경 설치는 [backend/README.md](backend/README.md)를 따른다.

```powershell
cd backend
# 명령 목록 확인만 수행
.venv\Scripts\python.exe -m midterm --help

# 로컬 스냅샷으로 총수요 모델·태양광 패턴 묶음을 재학습: 기존 net-demand.*를 갱신함
.venv\Scripts\python.exe -m midterm train

# 수요 계열을 과거 cutoff까지 학습하고 그 뒤 기간을 평가: 장시간 작업일 수 있음
.venv\Scripts\python.exe -m midterm backtest --cutoff 2025-09-30

# 입력 검토 후 새 연간 MILP 실행: 전국 1년 최적화를 실제 시작하는 명령
.venv\Scripts\python.exe -m midterm run --scenario inputs/my-scenario.json --quality normal --workers 4 --name annual-reviewed
```

`inputs/my-scenario.json`은 사용자가 검토해 준비할 파일명 예시다. 날짜·성장률·12개월 보정·예비율·원전/석탄 정비가 저장된 `Scenario` JSON이어야 한다. CLI `train`은 석탄 모델까지 재학습하지 않는다. 석탄 모델 학습 진입점은 `train_coal_curve_model(days)`이고 정답 튜플은 `(총수요, 석탄, 원전, 태양광)`이다. 새 석탄 모델을 활성화할 때는 별도의 시간순 검증과 모델 쌍 보존이 필요하다.

원천 DB 스냅샷을 갱신하는 `snapshot`은 연결정보와 자료 공개 승인이 필요한 별도 작업이다. 기존 모델 예측만 하려는 사용자는 실행할 필요가 없다. 현재 공휴일 선언 범위는 2023~2027년이며 2028년 이후를 실제 운영하려면 공휴일과 임시휴일을 먼저 보강·검증해야 한다. 윤년 시간 조립 테스트가 그 달력 내용까지 검증하는 것은 아니다.

## 11. 정확도와 적용 한계

- 총수요/순수요의 cutoff 백테스트는 [backtest.py](backend/src/midterm/backtest.py)를 사용한다. 이 도구의 석탄 비교는 실제 원전을 넣고 저장 석탄 모델을 사용하므로 원전 전망 오차를 포함한 연간 종합 검증이 아니며 석탄 학습 기간과 겹칠 수 있다.
- 저장 석탄 모델은 2026년 1~9월로 학습했다. 10~12월·새로운 수급 구조는 학습 범위 밖이다. 달력·월별 보정 입력이 있다고 표본외 정확도가 증명되는 것은 아니다.
- 평년기상은 실제 구름·폭염·한파의 발생 날짜를 예측하지 않는다. 과거 기상연도 재생도 미래 예보가 아닌 시나리오다.
- 정비 누락, 원전 출력·설비 증설/폐지, 성장률, 연료비·열량곡선 오차는 뒤 단계까지 전파된다. 정적 여유는 인증 예비력이 아니며 원천 P3 55일 결과를 이 연간 조건의 정확도나 안전성으로 전이하지 않는다.
- 단위 테스트·빌드는 구현 회귀 검사다. 365/366일 작업 조립은 합성 작업자 검사이며, 새 로직의 실제 전국 1년 실행시간·메모리·당진 정지 정확도·연간 물리 연속성 검증과 구분한다.
- 이 문서는 학습·실행 원리를 설명하며 모델 재학습·전국 1년 재계산·운영 채택·서버 배포를 수행했다는 증거가 아니다.
