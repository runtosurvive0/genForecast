# 2027 연료수급 연계 검증 초기 DB

`fuel-integration-2027.sqlite3`는 사용자가 2026-10-13 Git 공유를 요청한 가상 입력·결과·재고 원장이다.
2026-10-12 완료된 계산 `20261012-140843-140383-2027가상입력`에서 아래 자료만 추출했다.
계정·비밀번호·세션·AIS 관측·운영 발전실적·관계없는 선박·기존 전망 캐시는 포함하지 않는다.
수분·회분·황분은 미측정 `null`이며, 실제 0으로 표시하지 않는다.

| 테이블 | 건수 | 내용 |
|---|---:|---|
| `milp_inputs` | 1 | 2027-01-01~12-31 가상 시나리오·정비·월별 열량단가·기준 발열량·파일 체크섬 |
| `milp_runs` | 1 | 완료 요약과 8,760시간 × 58호기 NPZ 결과. 당진 10호기를 UI에서 조회 |
| `supply_baselines` | 3 | 계산 시작일 00:00 KST의 처별 가상 기준재고 |
| `supply_stock_lots` | 6 | 고열량 6,000 / 저열량 5,000 kcal/kg, 모두 사용자 가정 |
| `supply_vessels` | 1 | 계산에 귀속된 가상 선박 80,000t, 입하탄 5,900 kcal/kg, BD-1 |
| `supply_unload_points` | 1 | 2027-01-01 00:00 KST부터 7,000t/일, 1처로 배분 |

1처 고/저 50,000/90,000t, 2처 100,000/100,000t, 3처 150,000/150,000t, 합계 **640,000t**이다.
처별 혼합 발열량은 1처 5,357.142857, 2·3처 5,500 kcal/kg다.
월별 연료 구매계획 비교 기준은 기존 입력의 5,500 kcal/kg이며, 재고 소모는 처별 혼합 열량을 사용한다.
하역은 등록된 BD-1 한 곳만 반영한다. BD-2/3에 임의 화물을 만들지 않는다.
첫날 7,000t, 마지막 부분 하역 3,000t를 포함해 총 80,000t만 입고한다.

MILP 결과는 기존 공개 승인 모델과 가상 입력으로 계산한 `functional_demo`다. 실제 운영계획이나
실시간 실적을 뜻하지 않는다. 모델 학습기간, 풀이 상태·근사 해, 예측 경고를 원래 요약에 보존했다.
Pile별 적치 위치와 탄종별 소비 우선순위는 미지정이며, 기존 화면의 Pile은 별도 합성 표본이다.
초기 처별 DB 재고와 Pile별 실제 재고 연계 완료를 혼동하지 않는다.

## 등록·확인

`backend` 폴더에서 Python 의존성을 설치한 후 실행한다.

```powershell
.venv\Scripts\python.exe scripts/verify_shared_assets.py
.venv\Scripts\python.exe -m midterm seed-demo
```

기본 대상은 `MIDTERM_PLANNING_DB` 또는 `data/planning-local.sqlite3`다. 다른 격리 DB에는
`--database data/integration-test.sqlite3`로 등록한다. 공개 원본 `planning.sqlite3`와 초기 DB 자체를
대상으로 지정할 수 없다. 기존 설정·실적·원장을 보존하고 내부 ID를 새 DB에 맞게 연결한다.
전체 등록은 한 트랜잭션이며, 같은 계산 ID/기준재고 시각 충돌 시 등록 전체를 취소한다.
반복 실행은 `already_seeded`로 끝나고 이후 사용자 수정도 보존한다.

로컬 백엔드를 실행하고 프런트엔드를 해당 서버에 연결한 뒤, 데이터/관리자 → MILP 업로드의
실행 이력에서 **2027 가상입력 → 발전소 종합에서 보기**를 선택한다. 2027-01-01부터 30일을 조회해
초기 재고·일별 소비·월별 연료계획·호기 계획정지·일 7,000t 하역·처별 상탄을 확인한다.
당일 현재시각으로 조회하면 이 미래 가상 재고가 운영재고로 표시되지 않는 것이 정상이다.

Git pull/PR 병합만으로 공용 ZGX DB에 등록되지는 않는다. 공용 서버는 코드 배포 후 서버 담당자가
대상 `MIDTERM_PLANNING_DB`를 확인하고 같은 명령을 실행해야 한다. ZGX 장애 시 자동 등록하거나
로컬 가상 데이터로 대체하지 않는다. 인증 초기화는 별도이며 이 초기 DB에는 관리자 계정이 없다.
원본 크기·SHA-256과 공개 범위는 `../shared-assets.json`에 기록한다.
