# 당진본부 연료수급 종합화면 POC 디자인 스펙

- 기준일: 2026-10-08
- 범위: 당진본부 단일 POC
- 화면 방향: A형 위험·재고 중심 + 하단 FLOW/전망 결합
- 기본 전망기간: 30일, 7/30/60일 전환

## 1. 목적

첫 화면에서 다음 세 질문에 즉시 답할 수 있어야 한다.

1. 당진본부 전체 연료수급이 현재 안전한가?
2. 향후 수요·태양광·석탄발전·MIP 계획 때문에 석탄 사용량과 재고가 어떻게 변하는가?
3. 선박 입항·하역·처별 배분·저탄장·발전기 사용이 하나의 흐름으로 어떻게 연결되는가?

POC는 당진본부만 대상으로 하며, 다발전소 비교 기능은 포함하지 않는다.

## 2. 핵심 화면 구조

### 2.1 상단: 본부 연료수급 위험·재고 KPI

상단은 화면 진입 즉시 위험 여부를 판단하는 영역이다.

필수 KPI:

- 연료수급 상태: 정상 / 주의 / 위험
- 현재 추정 총재고(t)
- 재고일수(day)
- 현재 하역 중 물량(t)
- 향후 30일 입항예정 물량(t)
- 입항탄 가중평균 열량(kcal/kg)
- 금일 계획 기반 예상 석탄사용량(t/day, t/h)

재고일수 위험표시는 POC에서 다음 기본값을 사용한다.

- 정상: 15일 이상
- 주의: 7일 이상 15일 미만
- 위험: 7일 미만

임계값은 설정값으로 분리하고 화면에 하드코딩하지 않는다. 위 값은 POC용 초기값이며 향후 사내 운영기준으로 교체한다.

### 2.2 중단 좌측: 30일 전력수요·재생·석탄발전량 전망

하나의 대표 그래프에서 시스템 예측 흐름을 보여준다.

표시 항목:

- 전력수요 ML 예측
- 태양광 ML 예측
- 석탄발전량 ML 예측
- MIP 결과 기반 석탄발전 계획

목적은 모델 자체보다 결과 간 관계를 보여주는 것이다. Train/Validation Loss, RMSE 등 모델 품질 상세는 별도 모델 상세화면으로 분리한다.

### 2.3 중단 우측: 예측·최적화 핵심 지표

4개의 소형 카드로 구성한다.

- 수요 ML: 내일 최대수요, MAPE
- 태양광 ML: 내일 발전량, 정오 Peak
- 석탄 ML: 내일 석탄 필요발전량, 전일 대비 증감
- MIP 최적화: 기동예정 대수, 정지/DSS 대수, 예상 석탄사용량

각 카드는 작은 Sparkline만 제공한다. 첫 화면에서는 학습곡선을 전개하지 않는다.

### 2.4 하단 상부: 연료수급 FLOW

연료가 실제 업무 흐름상 어떻게 이동하는지 한 줄로 표현한다.

```text
선박(입항예정)
  -> 하역 중
  -> 처별 배분(1~4 / 5~8 / 9~10)
  -> 처별 저탄장 현재 추정재고
  -> 발전기 계획 기반 석탄사용
```

각 단계에는 핵심 수치만 표시한다.

- 선박: 입항예정 선박 수, 총 물량
- 하역: 현재 추정 누적 하역량, 잔여량
- 처별 배분: 각 처 배정 물량
- 저탄장: 각 처 현재 추정재고
- 발전기: 금일 및 30일 예상 석탄사용량

### 2.5 하단 하부: 전망 3종

1. 처별 재고일수 전망
   - 1~4호기 처
   - 5~8호기 처
   - 9~10호기 처
   - 정상/주의/위험 기준선

2. 처별 재고량 전망
   - 발전기 사용으로 감소
   - 하역·입고 시점에 증가
   - 이탄 입력 시 즉시 재계산

3. 호기별 이용률 및 예상 석탄사용량
   - 1~10호기
   - 이용률(%): 신뢰도발전계획 기반
   - 예상 석탄사용량(t/h 또는 t/day)

POC에서는 DCS 실시간값을 사용하지 않으므로 `현재 출력`이라는 표현을 사용하지 않는다. 화면에는 `계획 출력`, `계획 운전상태`, `계획 기반 예상 사용량`으로 표시한다.

## 3. 처별 관리 단위

당진본부는 다음 세 그룹을 별도 재고 단위로 관리한다.

- 1~4호기 처
- 5~8호기 처
- 9~10호기 처

각 처는 저탄장을 별도로 보유하며 다음 값을 독립적으로 계산한다.

- 기준 재고
- 현재 추정재고
- 평균 열량
- 금일 예상 사용량
- 향후 입고예정량
- 재고일수
- 7/30/60일 최저 예상재고

처간 이탄은 가능하며 POC에서는 자동 최적화하지 않는다. 운영자가 `출발 처`, `도착 처`, `이탄량`, `시각`을 수기로 입력하면 양쪽 재고를 즉시 보정한다.

## 4. 재고 데이터 기준

### 4.1 수기 기준재고

POC에서는 처별 재고톤수와 평균 성상을 수기로 입력한다.

필수 입력:

- 처 ID
- 기준 재고(t)
- 평균 열량(kcal/kg)
- 수분(%), 회분(%), 황분(%)
- 기준시각

모든 추정 계산은 마지막 기준시각 이후의 이벤트만 반영한다. 새 기준재고를 입력하면 이전 추정 누적값을 다시 더하지 않는다.

### 4.2 현재 추정재고

```text
현재 추정재고
= 마지막 수기 기준재고
+ 기준시각 이후 처별 누적 하역 반영량
+ 기준시각 이후 이탄 유입
- 기준시각 이후 이탄 유출
- 기준시각 이후 계획 기반 추정 석탄사용량
```

화면에는 반드시 다음을 함께 표시한다.

- 현재 추정재고
- 마지막 수기 기준재고
- 기준시각
- 순증감
- 데이터 구분: 수기 / 추정 / 예측

## 5. 선박 하역 및 처별 배분

### 5.1 하역 입력

자동 하역계측 연계가 없으므로 다음 값을 수기 입력한다.

- 선박 총 Cargo(t)
- 하역 시작시각
- 계획 하역속도(t/h)
- 처별 배분량 또는 배분비율

하역 중 운영자는 필요 시 `실제 누적 하역량`을 수기로 보정한다.

### 5.2 누적 하역 추정

보정값이 없는 경우:

```text
추정 누적 하역량
= 계획 하역속도 x 하역 시작 이후 경과시간
```

최근 보정값이 있는 경우:

```text
추정 누적 하역량(t)
= 최근 수기 누적 하역량
+ 계획 하역속도 x 최근 보정시각 이후 경과시간
```

결과는 선박 Cargo 총량을 초과할 수 없다.

### 5.3 처별 반영

현재까지 추정 또는 보정된 누적 하역량만 처별 현재재고에 반영한다.

아직 하역되지 않은 물량은 `입고예정`으로 유지한다.

한 선박이 여러 처로 배분되는 경우 누적 하역량을 설정된 처별 배분비율에 따라 나눈다. 운영자가 배분량을 변경하면 이후 미하역분에만 새 배분기준을 적용하는 것을 기본으로 한다.

## 6. 처간 이탄

POC 방식은 `이탄 가능 + 수기 이탄량 입력`이다.

입력값:

- 출발 처
- 도착 처
- 이탄량(t)
- 이탄시각
- 비고

재고 반영:

```text
출발 처 재고 -= 이탄량
도착 처 재고 += 이탄량
```

이탄속도, 최대 처리량, 소요시간 최적화는 POC 범위에서 제외한다.

## 7. 발전계획 기반 석탄사용량

### 7.1 발전량 데이터

POC에서는 DCS 대신 전력거래소 신뢰도발전계획 API의 호기별 계획 발전량을 사용한다.

향후 DCS 연계 시 동일한 계산 인터페이스에서 발전량 Source만 교체할 수 있어야 한다.

### 7.2 Heat Rate

- 실제 당진 1~10호기 Heat Rate 확보 시 수기 설정값 사용
- 값이 없으면 설비군별 표준 Heat Rate 기본값 사용
- 기본값 사용 여부를 화면 또는 관리자 데이터에서 구분 가능하게 한다

### 7.3 연소 열량

POC에서 호기별 석탄사용량 계산에 사용하는 열량은 해당 처 저탄장 전체 평균 열량이다.

하역 중 탄의 열량이나 입항예정 탄의 열량은 현재 연소열량으로 사용하지 않는다.

### 7.4 계산식

시간별 또는 계획구간별 계산:

```text
예상 석탄사용량(t)
= 계획 발전량(MWh)
  x Heat Rate(kcal/kWh)
  / 처별 저탄장 평균 열량(kcal/kg)
```

동일 처 호기의 사용량을 합산하여 처별 예상 사용량으로 사용한다.

## 8. 열량 관리

화면에서 다음 값을 혼동하지 않도록 분리한다.

- `yard_avg_cv`: 현재 처별 저탄장 평균 열량
- `incoming_cv`: 하역/입항예정 탄의 열량
- `burn_cv_estimate`: 연료사용량 계산에 사용한 열량

POC에서는 `burn_cv_estimate = yard_avg_cv`로 정의한다.

향후 Pile별 혼탄계획이 연계되면 호기별 실제 혼탄열량으로 교체 가능하다.

## 9. 예측·최적화 Pipeline

논리 흐름은 다음과 같다.

```text
전력수요 ML
  + 태양광 ML
      -> 석탄 필요발전량 ML
          -> MIP 발전기 배분
              -> 호기별 계획 발전량
                  -> 호기별 석탄사용량
                      -> 처별 재고전망
```

각 단계는 독립 결과를 저장하고 다음 단계가 이를 읽는 구조로 한다. 화면에서 직접 모델을 서로 호출하지 않는다.

첫 화면에는 각 모델의 대표 결과만 표시한다. 학습 Loss, Feature, MAE/RMSE 상세 등은 `예측모델 상세` 화면으로 분리한다.

## 10. 위험 판단

본부 전체 위험도는 세 처 중 가장 나쁜 상태를 기본 상태로 사용한다.

예:

```text
1~4호기 처: 정상
5~8호기 처: 주의
9~10호기 처: 정상
=> 당진본부 상태: 주의
```

위험판단 기준은 `현재 재고일수`가 아니라 선택한 전망기간 내 `최저 예상 재고일수`를 우선 사용한다.

입항 또는 하역 지연이 예상되면 해당 변경된 입고일정을 반영한 재고전망으로 다시 판단한다.

## 11. 데이터 신뢰도 표시

모든 주요 수치는 Source와 기준시각을 가져야 한다.

Source 유형:

- `MANUAL`: 수기 입력
- `API`: 신뢰도발전계획 등 외부 API
- `ESTIMATED`: 하역량, 석탄사용량 등 계산 추정
- `FORECAST`: ML/MIP 전망

첫 화면에는 카드마다 상세 출처를 길게 적지 않고 Badge 또는 Tooltip으로 제공한다.

예:

```text
현재 추정재고 162,000t  [추정]
기준 158,000t / 10월 8일 08:00 [수기]
```

## 12. POC 화면 상호작용

- 기본 기간: 30일
- 기간 선택: 7일 / 30일 / 60일
- 처별 그래프 Legend 클릭 시 해당 처 강조/숨김
- KPI 또는 Flow 단계 클릭 시 관련 상세화면으로 이동
- 이탄 수기 입력 후 재고/재고일수/위험도 즉시 재계산
- 하역 누적량 보정 입력 후 처별 재고와 입고잔여량 즉시 재계산
- 데이터 기준시각이 오래된 경우 Stale 표시

## 13. POC 제외 범위

- DCS 실시간 자동 연계
- 하역 Conveyor/Belt Scale 실시간 연계
- 자동 이탄 최적화
- Pile 전체 자동재고 계측
- 발전기 자동 기동/정지 지시
- MIP 결과 자동 운전지시
- 상업운영 수준의 자동 정산

## 14. 성공 기준

POC 첫 화면만 보고 사용자가 다음을 1분 이내 판단할 수 있으면 성공으로 본다.

1. 당진본부 전체 연료수급 위험 수준
2. 어느 처의 재고가 가장 먼저 위험해지는지
3. 향후 7/30/60일 입고와 사용을 고려한 재고 변화
4. 현재 하역 중 선박 물량이 각 처에 얼마나 반영되는지
5. 수요·태양광·석탄 ML과 MIP 결과가 발전기 계획과 석탄사용량에 어떻게 연결되는지
6. 향후 입항탄의 물량과 평균 열량이 충분한지

## 15. 승인된 화면 방향

승인된 시안은 다음 우선순위를 따른다.

```text
1순위: 본부 전체 위험·재고 KPI
2순위: 30일 수요/태양광/석탄발전 전망 + ML/MIP 핵심 지표
3순위: 선박 -> 하역 -> 처별배분 -> 저탄장 -> 발전기 FLOW
4순위: 처별 재고일수/재고량 전망 + 호기별 이용률/석탄사용량
```

처별 세부 카드와 호기별 상세표를 첫 화면 중앙에 크게 배치하지 않는다. 첫 화면은 `위험 판단과 향후 전망`에 집중하고, 상세 수치는 Drill-down 화면으로 이동한다.
