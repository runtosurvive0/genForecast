# gen4cast 운영 화면 통합

독립 HTML 시안의 화면과 3D 장면을 React 앱에 통합했다. 로그인·계정 승인·관심 선박·AIS·MILP·수급 원장은 기존 ZGX API 계약을 사용한다. iframe으로 시안을 삽입하지 않는다.

최근 로그인 디자인은 `w/genforecast-spectrum2`에 보존되어 있던 2026-11-03 작업본에서 복원했다. 처음 통합 기준인 main에는 이전 중앙 폼만 있어 누락됐던 부분이다. 왼쪽 소개·파란 수급 흐름과 오른쪽 폼, 모바일 폼 우선 배치를 그대로 유지하고 브랜드만 gen4cast로 맞췄다. 인증 콜백과 API 계약은 변경하지 않았다.

## 실행과 저장 범위

기본 실행은 기존과 같이 `npm ci`, `npm run dev`다. 프런트엔드는 기본 `http://127.0.0.1:5173/`, `/api`는 공용 **ZGX**를 사용한다. 별도 Python 서버나 AIS 키는 필요하지 않다. 저장 계산 조회와 실제 운전 계측은 구분한다.

이 작업의 기준 커밋은 `67ab2a3`, 통합 브랜치는 `codex/gen4cast-ui-integration`이다. 개발 파일 저장과 Git 커밋·원격 업로드는 별개다. 이 통합 작업은 아직 commit/push/배포하지 않았다. 원래 checkout의 사용자 DB와 문서 및 별도 시안 폴더는 유지한다.

## 화면 연결

| 주소 | 화면 / 기존 기능 연결 |
|---|---|
| `#overview` | 운영 개요: ZGX 저장 계획, 명시적 합성 시연 전환 |
| `#voyages` | 항차·화물: 기존 실제 AIS 지도·관심 항차·입하 원장 진입 |
| `#berth` | 접안·하역: 부두별 연결 설비·반입 가능 구역·하역 모사 |
| `#yard` | 저탄·재고: 1·2·3저탄장 참고 배치·지붕 투시·더미 선택 |
| `#blend` | 상탄·혼탄: 저탄장–상탄–벙커–보일러 공급 계통과 기존 원탄·혼탄 분석 보기 |
| `#units` | 호기·연소: 저장 계획과 별도 운전 모사 값, 실제 출력은 미연계 |
| `#simulation` | 통합 시뮬레이션: 동일한 저장 계획에서 수급·구매 검토로 연결 |
| `#procurement` | 구매 검토: 사용자가 입력한 입하일·리드타임·수량·운영용량·저장기간을 서버 전망과 대조 |
| `#costs` | 계획·실적 분석: 발전·연료 계획 및 자료 완전성, 미연계 실적을 0으로 대체하지 않음 |
| `#data` | 데이터 워크스페이스: 기존 MILP 업로드·실행·원천 데이터 |
| `#models` / `#schedule` / `#scenario` | 기존 모델·정지계획·단기 합성 시나리오 |
| `#fuel-ledger` | 기존 DB 재고·하역·입하 원장·수급 전망 |
| `#connections` / `#members` | 연결·수집 상태 / 실제 ZGX 계정 승인·권한 |
| `#demo-control` | 별도 탭의 로컬 운전 모사 조작반 |

구매 검토는 새 재고 예측 엔진이 아니다. 서버가 반환한 일별 재고에 조건을 대조하며, 발전처 총량과 실제 Pile 공간·탄종별 소비 가능성은 다르다. 단가·운임·배합·사용순서가 없는 상태에서 발주 추천을 만들지 않는다.

상탄·혼탄의 공급 계통은 1–4 / 5–8 / 9–10호기를 선택해 같은 저탄장 모델과 벙커·급탄기·미분기·보일러 개념 형상을 함께 본다. 확대·이동·지붕 투시·더미·호기 선택을 지원하고, 기존 분석과 발전처/기간 필터는 **혼탄 분석** 보기에 유지한다. Google Earth와 당진 전경·시공사 사진을 대조해 발전동을 저탄장 장축과 평행한 한 열로 배치하고 흰 외벽·파란 세로 패널·연속 터빈동을 표현했다. 사용자 원본 계통도의 CV-06/07/08, CV-55/56/57/58, CV-94/95/96/97/98 계열과 TTT-01/02/03 이후 호기 분기를 반영한다. 3저탄장 반출은 TT-96/97로 연결하며 반입 TT-95와 구분한다. 교차 공급과 절환 상태는 생략했고 건물 치수·투시로 확인하는 벙커 내부는 개념 표현이다. 상세 경로·형상 출처는 [구현 기록](superpowers/plans/2026-11-05-blend-scene.md)에 남겼다.

상탄 유량과 작업 누적량은 해당 저탄장에 속한 모사 작업에서만 읽고, 설비 흐름은 수신된 경로와 운전 신호가 있을 때만 움직인다. 연결 지연·단절 시 마지막 값을 유지하며 애니메이션을 멈춘다. 벙커 잔량·호기별 급탄량·혼탄비를 상탄 총량으로 만들어 내지 않으며 미연결로 표시한다. 화면에서 실제 배합이나 설비를 제어하지 않는다.

사용자의 2026-11-05 확인에 따라 1–10호기 모두 **사일로 6개 → 각 사일로 아래 작은 Coal Feeder → 그 아래 미분기**를 표현한다. 개수는 `silosPerUnit`을 장면과 공급 패널이 함께 사용한다. 사일로마다 상부 투입구와 하부 연결관을 연결하고, 분배 컨베이어 도달 범위·사일로 간 충돌·급탄기/미분기 상하 순서를 회귀 검사한다. 수량·연결 순서는 확인된 정보이며 세부 치수·간격과 내부 외형은 개념 표현이다.

## 위성영상 대조 배치 보정 (2026-11-06)

사용자가 제공한 접안부·전체 부지 이미지와 직접 열어 준 Google Earth 탭을 대조했다. 탭에 표시된 영상 촬영일은 **2024-04-12**, 확인일은 **2026-11-06**이다. 외곽 배치와 건물 관계를 반영하되 기존 아이소메트릭 일러스트 표현을 유지한다. 기본 접안 카메라는 비스듬한 직교투영이며 평면 보기를 별도로 제공한다. 영상 속 공사 상태와 선박은 확인일의 실제 운영 상태를 뜻하지 않는다.

- 접안 전체도는 육지에서 바다로 나가는 두 개의 긴 연결교와 그 끝의 분리된 잔교로 구성한다. 장면 방향 기준 왼쪽은 짧은 1부두, 오른쪽은 긴 2·3부두다. `berth-harbour.js`가 지지말뚝·레일·방충재·계선 돌핀·연결 보행로와 지붕 있는 반입 갤러리를 표현한다. 반복 간격·단면·색·부재 수량은 도식용이며 실측값이 아니다.
- `berth-site-layout.js`의 접안용 표시 변환을 설비·선박·재고 더미·흐름 입자·낙탄 목표점에 함께 적용한다. 1저탄장 장축의 1.3배 확대는 접안 전체도에만 적용한다. 저탄장 상세의 원본 치수, 2저탄장 보정값, 재고량과 연결 계통은 유지한다.
- 2저탄장 완성 지붕은 연결 통로 쪽 왼쪽 약 25%에 두고 나머지 노출 철골과 구분한다. 3저탄장은 2저탄장 뒤의 넓은 단일 태양광 지붕 외피로 표현하되 내부 A/B 저장 구역은 유지한다. 이 외피는 저탄·혼탄에서도 같은 모델을 사용하며 지붕 투시 조작은 유지한다.
- 혼탄은 저탄장 → 보일러 열 → 미분기룸·상부 트리퍼 → 터빈동의 관계를 공통 배치 자료로 정렬했다. 상탄 갤러리는 평면에서 직각으로 꺾여 보일러 사이 통로를 지나 TTT로 접근한다. 일반 보기에는 미분기룸 외피를 보이고, **발전동 투시**로 내부 사일로·급탄기·미분기를 확인한다. 발전동 투시와 저탄장 지붕 투시는 독립된 조작이다.
- 1920×1080에서는 약 400px 높이의 접안 장면, 오른쪽 3개 부두 선택 탭과 상세, 아래 일정·입항 목록을 한 화면에 둔다. 좁은 화면의 세로 흐름과 장면 조작은 기존 반응형 규칙을 따른다.

현재 `DESIGN.md`의 운영 파랑, Newsreader 브랜드, Pretendard UI, 회색 작업면·흰 패널·다크 대응과 선택 상태를 재사용한다. 금속·물·지붕 재질과 현장 외곽 보정은 장면 안의 일반 확장이며 전역 디자인 체계 변경이 아니다. `DESIGN.md`와 `.impeccable/design.json`은 이 문서 보정에서 변경하지 않는다. 출처와 치수 한계는 [설비 참고 기록](../src/data/fuel-reference/EQUIPMENT_REFERENCES.md)에 모았다. 검토 캡처는 로컬 `.impeccable/review/berth/`와 `.impeccable/review/blend/`에 있으며 운영 자료나 측량 성과가 아니다.

## 선택적으로 운전 모사 연결

추가 터미널에서 `npm run demo`를 실행하고, 앱 상단 **운전 데모**를 켠다. **조작반**은 별도 탭에서 열린다. 로컬 전용 WebSocket은 기본 61578 포트이며 실제 ZGX에 쓰지 않는다. 프런트엔드만 실행한 경우에는 연결 끊김과 재시도 상태를 표시한다.

기존 시안이 61578을 사용한다면 그 프로세스를 종료하지 않고 새 모사 서버에 별도 포트를 지정한다. PowerShell 예:

```powershell
$env:DEMO_PORT = '61579'
npm run demo
```

프런트엔드 `.env.local`에는 다음 값만 추가하고 Vite를 다시 시작한다. 실제 인증 API 기본값은 변경하지 않는다.

```dotenv
MIDTERM_DEMO_WS_TARGET=ws://127.0.0.1:61579
```

이번 로컬 확인에서는 시안 61577/61578을 유지하고, 통합 앱 5173 및 새 모사 서버 61579를 사용했다. 모사 상태는 메모리에 있으므로 재시작하면 초기값으로 돌아간다. 서버 ID 변경을 감지하고 이전 명령을 자동 재전송하지 않는다. 2초 이상 수신 지연 시 마지막 값을 표시하고 물류 애니메이션을 멈춘다.

## 데이터·구현 경계

- `src/components/operations-shell/`: gen4cast 브랜드, 공통 상단바·고정 파란 운영 패널.
- `src/components/fuel-scene/`: 재사용 Three.js 모듈. 확대·이동·투시·소진/적치·상부 이격과 자원 해제.
- `src/domain/fuel-demo/`, `scripts/fuel-demo/`: 단일 운전 모사 계약과 엔진. `demo-catalog.json`이 초기 물량의 공통 원천이다.
- `src/data/fuel-reference/`: 사용자 제공 사진에서 판독한 로컬 참고 수치. 공개 승인 자료로 새로 간주하지 않으며 원본 사진은 복사하지 않는다.
- 실제 DB 집계를 사진 속 Pile에 임의 배분하지 않는다. 1저탄장 오른쪽 50% 사용 제한은 사진 재고 위에 표시한다. 2저탄장의 이격 기준은 제공 표를 사용하며 3저탄장 미제공 기준은 만들지 않는다.
- 1920×1080의 접안·하역, 저탄·재고, 상탄·혼탄 공급 계통은 한 화면, 좁은 화면은 세로 배치다. 표는 필요한 경우 자체 스크롤한다. 데이터·분석 화면은 기존 긴 내용을 유지한다.
- 공통 변경: App, 전역 테마 토큰, 공통 차트 색, domain/data, 의존성 및 테스트 설정. PR 단계에서는 통합 담당자 리뷰 대상이다.

추가 의존성은 장면 렌더링용 `three@0.187.0`, 로컬 모사 서버용 개발 의존성 `ws@8.22.0`이다. 잠금 파일을 함께 변경했다. 글꼴은 자체 호스팅 Newsreader Medium과 Pretendard를 사용한다.

## 검증

`npm test`, `npm run build`, `npm run test:ui`를 사용한다. Windows에서 테스트용 Python이 별도 위치에 있으면 `AUTH_TEST_PYTHON`으로 지정한다. UI 테스트는 격리된 인증 DB와 HTTP 표본을 사용하며 공용 ZGX에 테스트 쓰기를 보내지 않는다. 추가 조작반 통합 검사는 `node tests/fuel-demo.test.ui.mjs`로 격리된 임시 WebSocket 서버에서 실행한다.

공통 화면 회귀는 `tests/integration-ui.spec.ts`, 물량·경로·연결 회귀는 `tests/fuel-reference.test.ts`와 `tests/fuel-demo*`, 계획·구매 조건 대조는 `tests/operations-workspaces.test.ts`에 있다.

2026-11-05 위성·원본 계통도·발전동 외관 대조 수정 후 최종 실행 결과: 단위 184개 및 빌드 통과. 전체 UI 97개가 한 실행에서 모두 통과했다(5.5분). 상탄 계통 전환·호기/더미 선택·확대·분석 전환·다크·1920/1131/390/320 화면 폭과 모사 상탄 수신/연결 단절 정지를 포함한다. 회원가입·승인·로그인·계정 격리와 복원 로그인 화면 검증도 포함한다. 최초 제한 환경의 단위 검사에서는 로컬 프록시/WebSocket 접속이 막혀 중단했고, 네트워크 접근을 허용한 격리 테스트로 전체 184개를 다시 통과했다. 독립 WebSocket 조작반 검증은 앞선 통합 단계에서 통과했다. `git diff --check`와 새 소스 공백 검사를 통과했으며 staged diff는 비어 있다.

UI 재검토에서 미수신 시각·접안 수, 모바일 데모 설명, 도면 레이블 겹침, 기존 패널 여백, 다크 헤더 아이콘, 두꺼운 강조선의 여섯 수정 항목이 모두 resolved로 판정됐다. 이 판정은 해당 여섯 항목에 한정하며 사람의 코드 리뷰 승인을 대체하지 않는다.

별도 계통도 대조 검토에서 발전동 배열, TTT 분기 위치, 2계통 중간 설비, 3계통 반입·반출 구분, 1저탄장 공용 반출 연결, A/B 이중 데크의 여섯 수정 항목이 모두 resolved로 판정됐다. 세 계통의 1920px, 다크, 1131/390/320px 캡처를 확인한 범위의 ship이며 실측 치수·설치 수량의 검증은 아니다. 변경 대상 디자인 검사 결과는 0건이고, 문서 검토에서는 기존 디자인 체계를 보존하는 일반 확장으로 확인했다.
