## 화면과 계산 경계

React 화면은 기존 다발전소 합성데이터 POC로 유지한다. Python 첫 화면은 당진 단일 계획·재고
POC이고 `/api/supply`의 내부 원장을 사용한다. React의 더미 수치가 Python 실계산 수치로
자동 전환되었다고 표시하지 않는다. Python 대시보드는 8093에서 별도로 실행한다.

공통 계약을 연결할 때는 다음 차이를 먼저 해결해야 한다.

| 항목 | React 기존 POC | Python 당진 서비스 |
|---|---|---|
| 호기 키 | 런타임 `dj-1`, `dj-2`, `dj-9` 표본 | `당진1`~`당진10` |
| 집계 경계 | 기준일 09시부터 24시간 | KST 00시~24시 |
| 재고 원천 | Pile별 합성자료 합계 | 1~4/5~8/9~10 처의 수기 기준 + 원장 |
| 연료량 | 효율 기반 에너지 환산 | 호기 열량곡선/수기 HR ÷ 발열량 |
| 미래 재고 | 연료가 부족하면 발전을 제한 | 승인 계획을 소비하며 음수는 계획상 부족량 |
| 기본 위험 기준 | 기존 SPEC의 20/30일 | 사용자 승인 당진 설계의 7/15일(DB 설정) |
| 전망기간 | 30/60/90일 | 이관 당시 7/30/60일, 후속 조회 연결에서 90일 추가 |

이번 이관은 계약 필드·React 공통 계산·SPEC 원문을 변경하지 않는다. 다음 연결 작업은 호기/시간

예비력을 0으로 만들어 채우면 안 된다. 팀 공통 계약 변경은 CONTRIBUTING에 따라 리뷰 후 merge한다.

React 계산 테스트와 타입 검사/빌드, Python 전체 테스트, 변경 파일의 공백 검사.

Git 추적 대상에 DB·실적·모델·runs가 포함되지 않는지 커밋 전에 확인한다.

2026-10-08 검증 결과: React 계산 테스트 28개 통과, 타입 검사/단일 HTML 빌드 통과.
Python 로컬 테스트 52개 통과. Git 추적 파일만 추출한 별도 체크아웃에서는 51개 통과,
저장 MIP 파일 확인 1개 skip. 새 8093 서비스의 연료 달력은 기존 8092 결과와 완전히 일치했고
두 모델 파일의 SHA-256도 일치했다. 실제 자료/모델 폴더의 추적 파일은 0개다.

기존 npm lockfile을 그대로 설치했을 때 audit가 `braces`와 상위 `micromatch`,
`vite-plugin-singlefile`을 high로 보고했다. 기존 빌드 의존성에 속하며 이번 이관에서는
package/lockfile을 변경하지 않았다. 자동 fix가 major 변경을 제안하므로 별도 검증이 필요하다.
현재 회사 Windows 환경의 npm TLS 연결은 기존 OS 신뢰 저장소를 사용하는
`NODE_USE_SYSTEM_CA=1`로 확인했다.
