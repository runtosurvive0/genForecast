# 회원가입·관리자 승인 설정

## 로그인은 되지만 선박 목록만 시간 초과되는 경우

4만 척 목록은 응답 크기가 커질 수 있다. 2026-10-12 ZGX 측정에서 일반 선박 JSON은 약 19.4MB, gzip은 약 3.1MB였다. 로그인 성공만으로 전체 목록 전송이 정상이라고 판단하지 않는다. 브라우저 Network에서 `/api/vessels/catalog`의 상태·소요 시간·전송 크기를 확인하며 쿠키나 토큰은 공유하지 않는다.

이번 수정은 `/api/vessels/catalog`에만 gzip 압축을 적용하고 프런트엔드 대기 시간을 12초에서 45초로 늘린다. 인증·계정 응답은 압축하지 않으며 승인 검사와 `Cache-Control: no-store`를 유지한다. 수신 한도·DB·AIS 키는 변경하지 않는다. ZGX 압축 업데이트는 기존 클라이언트에도 적용되지만 45초 대기는 프런트엔드 코드 업데이트와 Vite 재시작이 필요하다.

`scripts/deploy/zgx-catalog-compression.py`는 검증된 배포 묶음의 `manifest.json`과 함께 사용한다. 서버 app.py의 예상 해시가 맞을 때만 압축 미들웨어를 삽입하고, 기존 앱·DB·키·프런트엔드를 통째로 교체하지 않는다. `check`는 격리 검증만 수행하고, `apply`는 백업 후 서비스 재시작, `rollback BACKUP`은 이후 변경이 없는 경우 원복한다.

2026-10-12 ZGX에 압축 업데이트를 적용했으며, 사용자가 문제가 발생하던 다른 PC에서 선박 목록을 정상 조회했음을 확인했다. 백엔드·프런트엔드 서비스 정상 실행, 비로그인 목록 요청의 401 응답, AIS 상시 수집 유지도 확인했다. 45초 대기 변경은 별도 프런트엔드 업데이트가 필요하다.

온라인 앱은 로그인 후 사용합니다. 새 회원은 가입 신청 → 관리자 승인 → 다시 로그인 순서로 접속합니다. GitHub 계정과는 별도의 앱 계정입니다.

## 팀원이 개발 화면을 시작하기

저장소 루트에서 `npm ci` 후 `npm run dev`를 실행하고 `http://localhost:5173`에 접속합니다. 기본 설정은 ZGX 공용 서버를 사용하므로 개인 API 키나 Python 설치가 필요 없습니다. 회원가입 후 관리자 승인을 받고 본인 계정으로 로그인합니다. 기존 환경변수로 로컬 서버 주소를 지정했다면 아래 공용 서버 연결 절차를 확인하세요.

## 별도 로컬 백엔드를 처음 구성하기

이 절차는 공용 서버를 사용하는 팀원에게 필요하지 않습니다. Python 백엔드를 따로 개발하거나 새 서버를 구성하는 관리자를 위한 절차입니다. 먼저 `backend`의 의존성을 설치하고, 루트 `.env.local`에 `MIDTERM_API_TARGET=http://127.0.0.1:8093`을 설정합니다. 이전 `MIDTERM_API_ORIGIN`은 제거하고 Vite를 재시작합니다.

AIS·GFW 키를 설정한 PowerShell 창에서 실행 중인 서버를 `Ctrl+C`로 멈춥니다. **backend 폴더 기준** 다음 명령을 실행합니다. 같은 창을 사용하면 기존 API 키 환경변수가 유지됩니다.

```powershell
$env:PYTHONPATH = Join-Path $PWD 'src'
.\.venv\Scripts\python.exe -m midterm admin init
```

아이디, 표시 이름, 비밀번호와 확인 값을 차례로 입력합니다. 아이디는 영문 소문자·숫자·점·밑줄·하이픈 3~32자, 비밀번호는 공백을 포함해 8~128자입니다. 비밀번호 입력은 화면에 표시되지 않습니다. 채팅이나 Git에 비밀번호를 남기지 않습니다. 관리자가 이미 있으면 초기화 명령은 거부됩니다.

```powershell
.\.venv\Scripts\python.exe -m midterm serve --port 8093
```

프런트엔드의 기존 Vite 주소를 열고 새 관리자 계정으로 로그인합니다. **데이터/관리자 → 회원 관리 → 승인 대기**에서 신청자를 승인합니다. 승인받은 회원은 다시 로그인해야 합니다.

이 PC의 Python 의존성은 작업 중 설치했습니다. 다른 PC에서 이 변경을 받았다면 기존 backend 설치 절차에 따라 가상환경을 만든 후 다음을 실행합니다. 새 런타임 의존성 `argon2-cffi`는 비밀번호를 복호화할 수 없는 Argon2id 해시로 저장하는 데 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

## 계정과 관심 선박

- 승인된 회원: 앱 조회, 본인 관심 선박·항차·목적항 설정 저장, 본인 선박 항적·기상·기항 조회.
- 관리자: 위 기능과 회원 승인·거절·정지·복원·역할 변경, 공용 원장·설정 저장 및 서버 계산 실행.
- 미승인 회원: 승인 대기 안내와 로그아웃만 가능. API 직접 호출도 서버가 차단합니다.
- 로그인한 계정의 관심 선박은 서버에 저장합니다. 같은 서버를 사용하는 다른 기기에서도 같은 계정으로 불러옵니다. 계정 자료를 브라우저 localStorage에 저장하지 않습니다.
- 기존 브라우저 목록은 자동 귀속하지 않습니다. 본인 자료인지 확인한 뒤 **기존 관심 선박 가져오기**를 선택합니다. 항차와 유효한 목적항 선택도 가져오며, 같은 선박의 계정 목적항 설정이 있으면 우선합니다. 이전 브라우저 원본은 보존합니다.
- 동시에 다른 창에서 수정하면 버전 충돌을 표시합니다. 저장 실패 시 재시도하거나 미저장 변경을 버리고 서버 목록을 불러올 수 있습니다.
- 같은 브라우저의 탭들은 로그인 쿠키를 공유합니다. 다른 탭에서 로그인 계정을 바꾸면 기존 화면을 닫고, 서버도 요청의 예상 계정이 일치하는지 검사합니다.

일반 AIS 검색 수신 목록은 **120,000척**, 별도 한국행 후보는 **1,000척**입니다. 실제 수신 자료가 차오르는 최대 보관량이며 전 세계 선박 전체 목록이 아닙니다. **관심 목록은 계정당 200척, 서버의 실제 추적 대상은 계정 간 중복을 제외해 1,000척**으로 별도 제한합니다. 한도 초과 저장·계정 복원은 거절되며 이전 자료는 유지합니다.

12만 척 확대 시 서버와 프런트엔드를 함께 업데이트해야 합니다. 이전 프런트엔드는 4만 척 초과 응답을 거절하므로 배포 후 브라우저를 새로고침하세요. gzip과 화면 페이지 표시는 유지하지만 검색 목록 전체를 내려받는 구조이므로 느린 연결에서 전송 시간이 늘 수 있습니다. 서버 검색·페이지 처리는 후속 과제입니다.

## 보관·복구·서버 이전

계정·비밀번호 해시·세션·개인 목록은 `backend/data/access.sqlite3`, 항적은 `backend/data/vessel-tracks.sqlite3`에 저장합니다. 두 파일은 Git 제외 대상입니다. 공용 샘플 `planning.sqlite3`에 계정 정보를 넣지 않습니다. 서버를 멈춘 상태에서 두 파일을 별도로 백업하고, OS 계정의 파일 접근 권한을 제한합니다.

비밀번호를 잊었으면 서버 운영자가 다음 명령으로 임시 비밀번호를 정합니다. 기존 세션은 취소되고 다음 로그인에서 비밀번호 변경을 요구합니다. 정지 계정이 자동 복원되지는 않습니다.

```powershell
.\.venv\Scripts\python.exe -m midterm admin reset-password
```

세션은 최대 12시간, 화면 활동 없이 60분이면 만료됩니다. 승인 대기·비밀번호 변경 전용 세션은 30분입니다. 승인·정지·권한·비밀번호 변경 시 기존 세션이 취소됩니다.

기본 로컬 주소는 `http://localhost` 또는 `http://127.0.0.1`의 5173, 4173, 8090, 8093 포트입니다. 호스트 이름을 중간에 바꾸면 쿠키도 달라지므로 하나의 주소로 사용합니다. 다른 개발 포트는 `GENFORECAST_ORIGINS`에 정확한 origin을 쉼표로 구분해 등록합니다. `GENFORECAST_ACCESS_DB`로 계정 DB 경로를 별도 지정할 수 있습니다.

ZGX 공개 배포에서는 프런트엔드와 `/api`를 **동일 HTTPS origin**으로 프록시하고 `GENFORECAST_ORIGINS=https://실제호스트`를 설정합니다. 원격 HTTP origin은 허용하지 않습니다. 현재 ZGX 서비스와 상시 수집 구성은 [ZGX 업데이트 안내](HP_PERSISTENT_AIS.md)를 참고하세요.

### ZGX 공용 서버와 로컬 개발 화면 함께 사용

최신 코드에서 `npm ci` 후 `npm run dev`를 실행하면 PC의 `http://localhost:5173` 또는 `http://127.0.0.1:5173`이 ZGX 공개 HTTPS API에 자동 연결됩니다. 기본 주소는 `https://zgx-6660.tailec6d33.ts.net`입니다. 팀원별 API 키·Python 서버·DB·Tailscale·SSH 터널 설정은 필요 없습니다. 계정은 ZGX에서 가입하고 관리자가 승인합니다. 관리자 초기화 CLI는 공용 서버 관리자가 최초 한 번만 실행하며 팀원 PC마다 실행하지 않습니다.

기존 `.env.local`, `.env.development.local`, 셸 환경변수 등에 `MIDTERM_API_TARGET`·`MIDTERM_API_ORIGIN`이 있으면 기본값보다 우선합니다. 공통 ZGX 연결을 사용하려면 이전 값을 제거하고 Vite를 재시작합니다. 도메인 변경 등 다른 HTTPS 서버는 `MIDTERM_API_TARGET=https://새주소`로 지정하며 출처도 자동으로 맞춥니다.

Python 백엔드를 별도로 개발할 때만 루트 `.env.local`에 다음과 같이 설정합니다. 이때 `MIDTERM_API_ORIGIN`은 제거하고 해당 로컬 백엔드를 따로 실행합니다.

```dotenv
MIDTERM_DEV_PORT=5173
MIDTERM_API_TARGET=http://127.0.0.1:8093
```

`MIDTERM_API_ORIGIN`은 특별히 SSH 터널을 선택했을 때 전달할 ZGX의 정확한 HTTPS 출처를 지정하는 예외 설정입니다. 키가 아니며 일반 팀원 설정에는 필요 없습니다. HTTPS 인증서 검증은 항상 켭니다.

개발 프록시는 실제 연결이 loopback이고, Host가 해당 개발 서버의 localhost/127.0.0.1/::1 주소이며, Origin도 같은 주소일 때만 출처를 변환합니다. 외부 출처·다른 포트·Origin 없는 변경 요청은 ZGX에 전달하지 않습니다. 로그인·관리자 승인·CSRF 검사와 Secure/HttpOnly/SameSite 쿠키는 유지됩니다. 운영 서버의 허용 출처를 `*`로 넓히지 않습니다. `npm run preview`의 로컬 미리보기에도 같은 검사를 적용하며, 공개 배포 HTML에는 이 프록시가 포함되지 않습니다.

로컬 주소와 공개 HTTPS 주소의 로그인 쿠키는 별도이므로 각각 로그인합니다. 기본 설정에서 계정·관심 선박·DB는 동일한 ZGX 서버 것을 사용합니다. ZGX가 꺼지거나 인터넷 연결이 끊기면 오류를 표시하며 로컬 DB나 합성 데이터로 자동 전환하지 않습니다. 공용 데이터의 변경도 ZGX에 저장되므로 계정별 권한을 따릅니다.

AIS·GFW 키는 아직 기존 환경변수로 사용합니다. **관리자 화면의 공용 API 키 암호화 저장·교체 기능은 후속 작업**입니다. 회원가입 구현이 키 저장 기능까지 완료했다는 의미는 아닙니다. `file://` 오프라인 합성 시연은 인증 서버 없이 열리며 운영 API 접근 권한을 부여하지 않습니다.

## 검증

```powershell
# 저장소 루트
npm.cmd test
npm.cmd run build
npm.cmd run test:ui
# backend 폴더
.\.venv\Scripts\python.exe -m pytest tests/test_auth.py -q
```

UI 테스트는 8097 포트에 임시 DB를 사용하는 별도 Python 인증 서버를 띄웁니다. Python backend 개발 의존성이 필요하며, AIS/GFW 키를 테스트 서버에 전달하지 않습니다. 테스트용 계정은 이 격리 서버에만 생성합니다. 제품에는 인증을 해제하는 테스트 설정이나 기본 관리자 비밀번호가 없습니다.
