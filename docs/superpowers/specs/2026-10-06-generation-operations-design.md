# 발전운영 대시보드 설계

사용자는 기존 좌측 사이드바와 상단 바의 배치를 유지하면서 발전운영 중심 메뉴, 연료로 가능한 발전량, 발전기 정지계획, Thinking Orbs, 라이트/다크, 반응형을 전략 수립 후 적용하도록 요청했다.

## 선택
- React + TypeScript + Vite와 shadcn/ui를 사용한다. Spectrum 2는 일관된 Adobe 디자인/접근성이 강점이지만 현재 맞춤 레이아웃에 필요한 소스 소유·테마 조정은 shadcn이 적합하다.
- shadcn 공식 레지스트리의 실제 Button/Card/Badge/Select/Dialog 등 컴포넌트를 도입한다.
- 원본 thinking-orbs npm 패키지를 사용한다. https://github.com/Jakubantalik/thinking-orbs (MIT). 계산 중 solving, 자료 처리 중 searching. 처리 중에만 마운트하고 status 텍스트, 명시적 theme, reduced-motion을 지원한다.
- 현재 폴더는 git 저장소가 아니다. 원본 HTML을 보존하고 새 개발 소스와 더블클릭 가능한 단일 HTML 배포본을 추가한다.

## 화면과 상호작용
- 상단 바 60px, 좌측 사이드바 184px의 기존 구조를 유지한다. 모바일에서는 상단 바와 열기 버튼을 유지하고 사이드바는 접근 가능한 drawer로 제공한다.
- 메뉴: 발전운영 개요, 발전기 정지계획, 연료재고, 선박·입항, 시나리오 분석.
- 개요: 연료 환산 발전가능량(GWh), 현재 출력(MW), 최초 연료부족 예상, 가까운 계획정지; 재고 추이, 가동/정비 타임라인, 발전소별 운영표와 판단 근거.
- 정지계획: 계획정지(샘플 입력)와 연료부족 예측을 구분. 상세 패널에서 출처, 계산 조건, 기간, 영향을 확인한다.
- 시나리오: 부하 증감, 입항 지연, 입항 포함 여부, 전망 기간 변경. 기준안 대비 변화 표시. 입력 중과 적용 결과를 구분한다.
- 연료/선박 화면은 동일한 데이터로 표와 집계값을 생성한다. CSV 내보내기 제공.
- 실제 자료가 제공되지 않았으므로 모든 운영/정지계획 데이터는 샘플이다. 실시간·실제 정지라고 오인시키지 않는다.

## 계산 계약
- 기준시각 2026-10-06 09:00 KST, 4개 샘플 발전소. kcal/kg * 0.001163 = MWh/t. 전기생산가능량 = 질량 * 발열량환산 * 효율.
- 시간별 가동 부하와 계획정지에 따른 소비를 반영한다. 하역완료시각 이후부터 입항량 사용 가능. 재고가 부족하면 실제 공급 가능한 발전량까지만 계산한다. 음수 재고 금지.
- 발전소 재고는 그 발전소의 호기가 공유하며 다른 발전소 재고로 자동 보충하지 않는다. 계획정지/연료부족 시점은 별도 필드다.
- 일별 차트, KPI, 상세는 공통 계산 결과에서 파생한다. 전망 기간 내 부족이 없으면 기간 내 없음으로 표시한다.

## 품질
- 테마 시스템 기본값 + 수동 전환 저장. 읽기 쉬운 타이포, 의미 있는 상태 색상, 대비, 키보드 포커스.
- 데스크톱/태블릿/390px 모바일 및 두 테마 확인. 페이지 가로 넘침 금지, 긴 표는 자체 스크롤.
- 계산 단위/정지시간/입항지연/영재고를 자동 테스트. 빌드·타입 검사·브라우저 기능/스크린샷 검증.
