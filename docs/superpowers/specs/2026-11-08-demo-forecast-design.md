# 11월 10일 시연: 예측 모드·시연 상황·어시스턴트 설계

## 목적

현재 모드(모의 운전 엔진)와 같은 시작 재고·선박·부두로 D+90까지의 수급을 계산해 보여 준다.
시연 상황 4개(입항 지연, 반입 CV 고장, 발전량 급증, 상탄 전략 변경)를 넣으면 계획이 바뀌는 모습을 보인다.
어시스턴트는 자연어 지시를 계산 조건으로 바꾸고, 접안·적치 대안을 비교해 추천한다. 결정은 사람이 한다.

## 데이터 원칙

- 모든 입력은 가상 표본이다. 화면에 "가상 표본 · 실제 운영 정보 아님"을 표시한다.
- 시작 재고는 현재 모드 카탈로그(`demo-catalog.json`)의 저탄장별 고·저열량 재고를 쓴다.
- 선박 5척은 접안·하역 화면의 예시 항차와 같다. 이후 계약 선박은 가상으로 추가한다. 산지명은 실제, 성상은 가상이다.
- 체선료 요율은 기존 예제 값(하루 18,000달러)을 가정으로 쓴다.

## 구성

- `src/domain/demo-forecast/engine.ts`: 시간 단위 계산. 입항 → 부두 대기열 → 하역(부두 속도·CV 가용률·저탄장 여유) → 저탄장 탄종별 재고 → 호기 연소(급전 계획 × 열소비율 ÷ 혼탄 발열량). 결과는 일별 재고, 선박 일정, 고갈 시점, 체선 시간·비용이다.
- `src/domain/demo-forecast/scenarios.ts`: 시연 상황 4개를 입력 변경으로 정의한다.
- `src/domain/demo-forecast/assistant.ts`: 규칙 기반 자연어 해석(LLM 백업), 서버 해석 결과 재검증, 대안 비교(배정 방식별 재계산과 이적안 탐색·순위).
- `backend/src/midterm/demo_assistant.py`, `backend/src/midterm/web/assistant_api.py`: `POST /api/demo-forecast/interpret`. OpenAI Responses API(구조화 출력)로 지시를 계산 조건 JSON으로 바꾸고, 선박·부두 목록과 값 범위를 검증한 항목만 돌려준다. 계산은 하지 않고 공용 자료도 바꾸지 않는다. 사용자별 분당 20회로 제한한다.
- 화면은 서버 해석을 먼저 시도하고, 미설정(503)·연결 실패·오프라인 파일이면 규칙 해석으로 대신하며 어느 쪽을 썼는지 표시한다.

## LLM 설정 (ZGX 환경 변수, Git에 넣지 않음)

- `GENFORECAST_ASSISTANT_LLM=1`: 사용. 설정하지 않으면 503을 돌려주고 화면은 규칙 해석을 쓴다.
- `OPENAI_API_KEY`: OpenAI API 키.
- `GENFORECAST_ASSISTANT_MODEL`: 모델 이름. 기본 `gpt-5.5`.
- 의존성 `openai==3.46.0`(및 `jiter`, `sniffio`)을 `backend/requirements.lock`에 추가했다. ZGX 배포 때 설치가 필요하다.
- `src/data/demo-forecast-sample.ts`: 가상 표본 입력.
- `src/features/forecast/`: 예측 화면. 기간(7·30·60·90일), 상황 버튼, 어시스턴트 입력, 재고 그래프, 부두 일정표, 대안 비교표.

## 계산 규칙

- 부두는 한 번에 한 척. 하역 완료 후 6시간 뒤 다음 배가 접안한다.
- 저탄장 여유가 없으면 하역이 멈추고 대기 시간이 늘어난다.
- 상탄 전략은 고열량:저열량 비율을 정한다. 한쪽이 바닥나면 다른 쪽으로 대체하고 기록한다.
- 재고일수 = 재고 ÷ 다음 7일 평균 소비. 7일 미만 위험, 15일 미만 주의(앱 기존 기준).
- 고갈 시점은 탄종별·발전소 전체로 계산한다.
- 체선: 허용시간(물량 ÷ 하루 4만 t + 24시간)을 넘긴 체류 시간 × 요율.
