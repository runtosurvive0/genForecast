# 한국행 AIS 후보 검색

사용자 승인 범위: 전 세계 수신 유지, 서버 목적지 분류, 별도 후보 보존, 검색 범위 세 가지 추가.
브랜치: `feature/vessels-tracking`. 기존 미커밋 변경을 보존하며 커밋·push·merge하지 않는다.

## 구현과 검증 순서

1. 한국행/출항 방향/모호한 문자열, 일반 캐시 퇴출, 목적지 변경·만료, 관심 등록 회귀 테스트를 먼저 추가하고 실패를 확인한다.
2. 서버 전용 목적지 사전과 후보 캐시를 구현한다. 기존 `vessels` 계약은 유지하고 선택적 후보 배열만 추가한다. 목적지와 위치 시각을 분리한다.
3. 검색 UI에 범위·판별 근거·목적지 시각을 연결한다. 중복 제거, 구 서버 호환, 등록·테마·반응형·고정 창 높이를 확인한다.
4. 전체 Python/프런트 테스트, 빌드, UI 테스트, 별도 코드 리뷰, 변경 diff를 확인한다. 키를 보유한 사용자 터미널에서 서버를 재시작한 뒤 실제 응답을 점검한다.

## 경계

- 일반 4,000척, 후보 1,000척/72시간 메모리. DB 변경 없음, 서버 재시작 시 후보 재수집.
- 공개 UNECE 항만·지역 코드의 선별 사전. 자유 입력의 오기·모호함·미등록 목적지는 누락 가능.
- 선박명·국적·현재 좌표로 한국행을 추정하지 않는다. 후보는 확정 목적항·석탄 선적 정보가 아니다.
- 사용자 관심 등록과 목적항 확인을 유지한다. 항차·연료 입하·재고 원장 변경 없음.

## 완료 기록

- 서버 분류·별도 보존, 목적지/정적 정보/위치의 독립 시각 처리, 후보의 관심 등록 연결 구현.
- UI 검색 범위·판별 근거·목적지 시각·MMSI 중복 제거·구 서버 호환 구현. 창 높이 유지, 큰 화면 내부 넘침, 모바일 등록 버튼, 라이트/다크 확인.
- `npm.cmd test`: 79개 통과. `npm.cmd run build`: 통과.
- 백엔드 전체 `python -m pytest -q`: 117개 통과.
- `npm.cmd run test:ui`: 58개 통과. 로그 `.tooling-tmp/korea-final-ui.log`.
- 별도 코드 리뷰에서 목적지 없는 정적 메시지가 지연 목적지 갱신을 막는 문제를 재현·수정했다. 후보 생성/해제와 최신 이름·선종 보존 회귀 테스트 추가, 재검토 결과 추가 P1/P2 없음.
- 실제 수신 문자열에서 공식 마산 코드 `KR MAS`를 추가했다. 확인하지 못한 `KR KWY`, 외국 지명 `KRISTIANDSAND`, `KRIMPEN AAN DE IJSSE`, `NO KRS`는 자동 한국행 판별에서 제외하는 테스트를 추가했다.
- 사용자가 기존 키 터미널에서 재시작 완료. 로컬 서버 `receiving`, 새 후보 API(1,000척/72시간), 재수집 시작 확인. 초기 후보 0척은 목적지 메시지 수신 전 상태이며 합성 결과로 채우지 않는다.
- 브랜치 `feature/vessels-tracking`. 기존 작업 보존, 커밋·push·PR·merge 없음.
