# 오늘부터 실행하는 전망과 추가 데이터

기준: 2026-11-09, `전망고도화` 브랜치. 아래 준비 상태는 Git에 포함된 공개 스냅샷을 확인한 결과다. ZGX 운영 DB의 최신 상태를 뜻하지 않는다.

## 후속 CSV 입력 반영

사용자 제공 CSV를 Git 제외 작업 DB의 입력에 보관하도록 보완했다. 석탄·원전 제원, 연월별 열량단가와 정비를 입력에 함께 고정하며 결과의 연료량 환산에도 같은 제원을 쓴다. 기존 공개 스냅샷을 아래에서 설명한 초기 준비 상태와 구분한다.

- 단가 CSV의 천 단위 쉼표를 처리하고 날짜 두 칸이 빈 정비 행은 일정 미등록으로 읽는다.
- 2026년 11·12월은 2026년 1~10월 단가로 호기별 선형 회귀해 보완한다. 2027년 첨부 단가는 원본 값으로 보존한다. 회귀식·학습 범위·마지막 2개월 구간 검증·추정 분류를 DB에 저장한다.
- 화면에서 입력을 복사하거나 단가를 수정할 때 제원·연월 단가·회귀 이력을 함께 전달한다. 정지계획 메뉴는 활성 DB 입력의 전국 석탄·원전 일정을 조회한다.
- 실제 저탄장 원장은 동일 서비스의 공통 수급 엔진으로 연결한다. 2026-11-09 확인 시 ZGX 원장 API는 인증 없는 요청에 `401 login_required`를 반환했고 실제 운영 재고를 조회하지 못했다. 작업 DB에 실제 재고를 임의 생성하지 않았다. 운영 DB 연계 검증에는 인증된 연결 또는 DB 파일 경로가 필요하다.

후속 입력 검증은 단위 241개, 관련 백엔드 51개, 입력·정지계획 브라우저 11개와 빌드가 통과했다. 사용자 CSV 기준 2026-11-09~2027-02-06 MILP도 실행해 작업 DB에 결과를 저장했다. 94개 창은 `approximate` 20개·`time_limit_feasible` 74개로, 최적성이 증명된 결과로 표시하지 않는다. 저장 결과의 첫날 연료 환산은 고정한 제원으로 별도 재계산해 대조했다. 실제 재고·성상·하역 연결 검증은 인증 접근이 없어 남아 있다.

```powershell
$env:PYTHONPATH = "$PWD\backend\src"
# 파일 경로는 사용자가 보유한 CSV 경로로 지정한다.
.\backend\.venv\Scripts\python.exe -m midterm.reference_data --coal-units coal-units.csv --nuclear-units nuclear-units.csv --heat-prices prices-2027.csv --coal-oh coal-oh.csv --nuclear-oh nuclear-oh.csv
# 등록된 입력 ID를 지정해 DB 제원·단가·정비로 실행한다.
.\backend\.venv\Scripts\python.exe -m midterm run --input-id 1 --quality fast --workers 4
```

다른 작업 DB를 선택하면 `MIDTERM_PLANNING_DB`를 그 경로로 설정한 환경에서 서버·계산을 실행한다. 기존 DB를 먼저 백업하며 공유 원본 `planning.sqlite3`에 실제 입력을 덮어쓰지 않는다.
원전의 가동 개시일을 별도 가정으로 지정할 때는 `--activate-nuclear-unit 호기=YYYY-MM-DD`를 명시하며 원본 활성값과 가동일 변경 출처를 함께 보존한다.

## 실행 방법과 날짜 기준

- 새 MILP 기본 시나리오는 **실행 시 한국시간 오늘부터 90일**, 시작일·종료일 포함이다. 2026-11-09에 만들면 2027-02-06까지다. `/api/meta`의 `default_scenario`와 `python -m midterm run`이 이 기본값을 사용한다.
- 발전소 전망의 **조건 설정 → 저장 조건 불러오기 → 오늘부터 90일 → 저장 후 전망 실행**으로 기존 단가·정비 조건을 복사해 새 계산을 실행한다. 불러온 원본과 과거 계산은 그대로 보관한다. 새 입력의 정비·단가 적용 기간을 먼저 확인한다.
- 데이터/관리자의 **전망 입력·계산 → 기본 조건에서 작성**도 오늘부터 시작한다. 관리자 권한이 필요한 저장·실행은 기존 권한 검사를 유지한다.
- 저장 결과 중 오늘부터 최소 7일을 조회할 수 있는 계획이 있으면 이를 우선 선택한다. 선택한 계획의 잔여 기간이 30일 이상이면 오늘부터 30일, 7~29일이면 7일을 조회한다. 미래·과거 계산을 오늘 날짜로 옮겨 표시하지 않는다.
- **수급 예측** 화면의 별도 모의 엔진도 한국시간 오늘 00:00부터 시작한다. 열린 화면은 1분마다 날짜를 확인한다. 미래 발전량과 계약 선박은 가상 표본이며 MILP 결과가 아니다. 운전 모사 연결은 현재 재고·하역 잔량·첫날 출력만 바꾼다.
- 날짜는 일 단위 KST다. '오늘부터'는 오늘 **00:00** 기준 전망이며, 현재 시각까지의 실적을 자동 합성하는 기능은 아니다.
- 모의 엔진의 90일 전망에는 고갈 탐색 60일과 재고일수 산정용 7일을 더해 **157일의 호기별 일 발전계획**이 필요하다. 부족한 배열·빈 값·음수·비정상 값은 오류로 처리한다. 마지막 값을 반복하거나 누락을 0으로 채우지 않는다. 현재 표본은 157일을 생성한다.

CLI는 프로젝트 Python 환경에서 실행한다. 최적화 엔진은 저장소에서 검증한 `highspy==1.12.0`이 필요하며 다른 버전은 실행을 거부한다. 이 PC의 `backend/.venv`에 지정 버전을 설치했다. 다음 명령은 기본 공개 조건을 사용하므로 아래 정비·단가를 확인한 검토용 실행에 해당한다.

```powershell
$env:PYTHONPATH = "$PWD\backend\src"
.\backend\.venv\Scripts\python.exe -m midterm run --quality normal --workers 4
```

## 기준재고와 입하 중복을 피하는 기준

- 날짜만 있는 `yard_baselines`는 기준일의 마감량으로 해석해 **다음 날 00:00 KST**부터 적용한다. 2026-11-09 00:00 전망이라면 11월 8일 마감 기준량이 대응한다. 모의 운전의 현재 순간 재고는 이 일 마감 원장과 별개다.
- 기준시각 이전에 이미 하역한 물량은 시작재고에 들어간 것으로 보고 이후 입하에 다시 더하지 않는다. 하역 중인 배에는 총 화물량과 누적 하역량을 함께 제공한다.
- 양이 있는 각 재고 구간의 발열량과 분석 기준을 확인한다. 항차·탄종이 모호하거나 성상이 없으면 해당 처의 연소량·재고전망은 미확정으로 유지한다. 임시 5,500 kcal/kg 환산은 구매계획의 가정이며 성상 확인을 대체하지 않는다.
- ID 예: 서버 `당진1`~`당진10` ↔ 화면 `dj-1`~`dj-10`; 처 `g14/g58/g910` ↔ 모의 저탄장 `Y1/Y2/Y3`. 변환표를 공급원마다 확인한다.

## 검증 범위

날짜 이동, 자정 갱신, 연도 경계, 계획 누락 거부와 기존 저장 입력 보존을 회귀 테스트한다. 모의 계산 성공은 실제 데이터 기반 MILP 완료나 운영 재고의 정확성을 뜻하지 않는다. 최신 운영 데이터 확보·업로드와 새 MILP 계산은 별도 실행 단계다.

2026-11-09 로컬 검증 결과:

- `npm test`: 241개 통과. 주말 발전계획이 새 시작일을 따르는 추가 확인도 통과.
- 프로젝트 Python 환경의 시나리오·입력 저장·MILP 작업자·수급 API 관련 테스트: 43개 통과.
- `npm run build`, `git diff --check`: 통과. 단일 HTML의 오프라인 계산, 라이트·다크·좁은 화면 확인.
- 오늘부터 90일 MILP 입력 준비: 전국 석탄 58기, 예열 포함 2,208시간. 전국 90일 전체 최적화의 성능·gap 검증은 별도 실행 사항.
