# 항차·화물 원장

항차·화물 페이지의 **항차 DB**에서 배선 원장, 화물 원장, 성상 분석, 선박 관리를 연다. 승인된 팀원 모두 입력·수정·엑셀 반영할 수 있다. 검색은 연결된 배선·선박·화물 정보도 포함하며 상태·분석구분·날짜로 좁힌다.

## 배선과 화물 입력

- 개별 입력: 배선 등록 → 기본정보·선박·일정·화물·계약 작성 → 변경 내용 확인 → 공용 원장에 반영.
- 계획명 없이 배선을 먼저 저장할 수 있다. 선박·화물·항차번호는 나중에 연결한다.
- 항차번호 `26-1-019`는 연도·부두·입항 일련번호다. 저탄장은 별도 항목이며 `1-19`는 입력 시점의 KST 연도로 보완한다. 배선 입력 화면은 같은 연도·부두의 현재 원장에서 마지막 번호 다음을 추천하며, 최종 저장 시 중복과 원장 변경을 검사한다.
- 내부 관리ID는 자동 생성한다. 정식 항차번호를 부여·수정해도 화물·분석·이력이 같은 배선에 유지된다.
- 선박은 선박명으로 등록하고 아는 IMO·MMSI만 입력한다. 내부 선박 관리ID는 공식 선박 식별자가 아니다. AIS 수신 가능 여부와 원장 등록은 별개다.
- 같은 배선에 여러 탄종·공급사·계약 화물을 추가할 수 있다. 각 화물에는 목적발전소, 예정물량 또는 B/L물량이 필요하다.
- 용선구분, 선적항·국가, LAYCAN, 선적항 ETA/ETB/ETD, 예정·실제 하역 일정, 노미네이션, 계약구분·조건·번호·날짜를 기록한다. 선박 국적과 선적항 국가는 별도다.
- **입고 시작일·종료일은 석탄이 들어온 날짜**, 입하량은 t이다. 선박 입항·접안 시각이나 B/L물량과 구분한다. 입력만으로 재고를 가산하지 않는다.

## 성상 분석

화물에 연결하여 선적·하역·바이어 샘플을 각각 등록한다. 재분석은 새 분석 건으로 추가하고 시료번호·성적서번호·채취일·분석일·기관·결과상태를 보관한다. 목록에는 항차, 탄종, 산지, 입고 시작/종료일, 입하량을 연결해 표시한다.

| 묶음 | 항목·단위 |
|---|---|
| 발열량·기본 성상 | ARB, ADB, DB, NCV 각각 kcal/kg; NCV 기준; 총수분 AR, 유황분 AR %wt; HGI |
| 공업분석 | ADB %wt: IM, VM, Ash, FC |
| 원소분석 | DB %wt: C, H, N, O, S; Ash는 별도 계산값 |
| 회성분 분석 | %wt: SiO2, Al2O3, CaO, MgO, Na2O, K2O, SO3, TiO2, 기타 |
| 연료특성 | 연소시작·종료·최대연소온도 °C, 최대연소속도 %/min |
| 회융점 | 환원성 °C: IT, ST, HT, FT |
| 입도·염소·점결성 | 2mm 이하·0.25mm 이하 %wt, 염소 DB ppm, CSN |

대표 성상은 **확정 하역 분석 우선, 없으면 확정 선적 분석**이다. 같은 구분 안에서는 분석일 → 채취일 → 수정시각 → 관리ID 내림차순으로 선택한다. 바이어 샘플과 미확정 결과는 자동 대표값에 사용하지 않는다. 분석 건 전체를 선택하며 빈 항목을 다른 분석으로 채우지 않는다. 빈칸은 미측정이고 0은 입력된 0이다.

`Ash(DB) = Ash(ADB) × 100 ÷ (100 − IM(ADB))`. 회분 또는 고유수분이 없으면 계산하지 않는다. 총수분으로 대체하지 않으며 원본 분석값을 덮어쓰지 않는다. [ALS 기준환산 안내](https://www.alsglobal.com/en/coal/borecore-analysis/coal-basis-conversion)를 따른다.

NCV 기준은 확인 전 `미확인`으로 보관한다. 기준 미확인 값의 자동 환산·혼탄 계산은 하지 않는다. 조건별 혼탄 검토에는 확인된 대표 성상의 ARB 발열량을 사용한다.

## 엑셀 일괄등록

1. 신규는 **엑셀 양식**, 기존 수정은 **전체 내보내기**를 사용한다.
2. `배선등록`: 화물 한 건당 한 행. 항차번호가 미정인 배선에 여러 화물이 있다면 같은 `배선 묶음`과 서로 다른 화물순번 1, 2, 3을 쓴다. 화물 없는 배선과 묶음 없는 단일 행도 가능하다.
3. `성상분석`: 분석 한 건당 한 행. 같은 파일의 항차번호 또는 배선 묶음 + 화물순번으로 연결한다. 기존 화물은 내보낸 숨김 화물 관리ID를 보존한다. 이전 `계획명` 헤더를 쓰는 양식은 계속 읽는다.
4. `선박관리`: 아직 배선에 연결되지 않은 선박의 보존·수정용이다. 신규 배선의 선박은 배선등록에서 함께 입력한다.
5. **엑셀 가져오기**에서 추가·수정·오류·변경 전후를 확인하고 전체 반영한다. 오류가 있으면 일부만 저장하지 않는다.

헤더 순서는 자유지만 양식의 열은 유지한다. 단위와 분석 기준을 헤더/항목안내에 표시한다. 선택값은 한글 드롭다운을 사용한다. 관리ID는 숨김이며 사용자 입력 대상으로 삼지 않는다. 재분석은 시료번호·성적서번호로 구분한다.

- 포함 행의 빈 선택값은 기존 값을 비운다. 빠진 행은 삭제하지 않는다. 기존 수정 시 내보내기의 관리ID를 보존한다.
- MMSI/IMO는 텍스트로 보존한다. 수식·매크로·오류 셀은 허용하지 않는다. XLSX 4MB, 원장 총 5,000행 한도다.
- 일정 역전, 중복 항차번호·식별자, 연결 누락, 음수 물량, 성상 범위, 0.25mm 누적비율 > 2mm 누적비율 등을 검증한다.
- 내보낸 원장 버전이 오래되면 전후 비교 후 별도 확인한다. 검토 이후 다른 사람이 수정하면 충돌로 중단한다.
- 최근 100건 변경 이력을 화면에 표시하고 전체 이력은 DB에 보존한다.

## 저장·배포 경계

수기/엑셀 화물 등록만으로 재고를 더하지 않는다. 실제 하역완료 시각·입고 종료일·입하량을 기록한 후 **Pile 재고**에서 실제 위치와 물량을 명시하면 화물과 연결된 수기 재고가 생성된다. 분할 배분 합계는 입하량과 같아야 하며 화물 중복 반영을 막는다. 이후 잔량 변경은 사유·작성자·시각과 함께 기록하며 실시간 계측값이 아니다.

왼쪽 메뉴의 **재고 원장**, 저탄·재고 화면의 재고 원장 버튼과 `#inventory`는 같은 Pile 원장을 연다. 기존 기준재고·수급 전망 화면은 **수급 원장** 또는 기존 `#fuel-ledger` 주소에서 계속 조회할 수 있다. 항차·화물 화면의 **항차 DB**는 공용 배선 원장을, **입하·화물 원장**은 같은 공용 원장의 화물 탭을 연다.

배분 당시의 입고 종료일과 하역완료 시각은 별도로 보존한다. 원본의 입하량이나 완료 정보가 이후 변경되면 재확인 상태로 표시하고 혼탄·수급에 임의로 반영하지 않는다. **배분 정정**에서는 화물의 전체 Pile·셀, 최초 적치량과 현재 잔량을 다시 입력하고 사유를 기록한다. 새 적치량 합계는 원본 입하량과 같아야 하며 정정 전후 내역과 작성자를 함께 보존한다. 승인된 팀원이 정정할 수 있다.

수급 전망은 처별 기준재고 시각 이후의 확인된 입하만 더한다. 기존 수급 선박과 중복 가능성이 있거나 기준 성상이 없으면 임의로 계산하지 않고 확인 필요로 둔다. Pile 잔량 수정 이후에는 처별 소진 배분을 알 수 없으므로 새로운 기준재고 확인이 필요하다. 사진 기반 3D 더미는 이 원장과 별개의 참고 자료이며 위치·형상을 자동 추측하지 않는다.

배분 정정 이전 시점 전망은 그 시점의 이전 배분을 사용한다. 정정 후에는 기존 및 새 위치의 발전처에서 정정 이후 기준재고를 다시 입력하기 전까지 전망 재고를 미확정으로 둔다. 이를 통해 정정 전 기준재고에 이미 포함된 입하를 새로운 위치에 다시 더하지 않는다.

저탄·재고의 도면 상단에는 선택 저탄장에 등록된 수기 재고를 Pile 또는 셀별로 합산해 별도 표시한다. 등록되지 않은 구역은 재고 미확인이며, 원장 정보가 변경된 항목은 재확인으로 표기한다. 이 수치는 도면의 사진 기준 더미 형상이나 사진 기준 KPI를 바꾸지 않는다.

상탄·혼탄의 조건별 혼탄 검토는 수기 재고의 확정 하역 분석을 우선하고 없으면 확정 선적 분석을 사용한다. ARB 발열량 목표와 허용오차, AR 총수분·유황분 상한을 입력해 가용량 내 조건 충족 조합을 계산하고 목표 발열량과의 차이를 최소화한다. 다른 성상·설비 제한은 계산하지 않으며 실제 운전 지시가 아니다. NCV 기준 미확인 값은 사용하지 않는다.

기존 ZGX Python/SQLite와 openpyxl을 재사용한다. 새 의존성은 없다. `MIDTERM_PLANNING_DB`의 `voyage_registry_*` 및 `stock_inventory_*` 테이블을 사용한다. DB 파일은 Git에 넣지 않는다.

이 연계의 공용 사용 전에는 ZGX 백엔드 업데이트·재시작이 필요하다. 운영 절차에 따라 DB 백업 후 적용한다. 연결 실패를 로컬 또는 합성 저장으로 대체하지 않는다.

## API

공통 경로 `/api/voyage-registry`:

| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/schema`, `/records` | 필드 계약, 레코드·revision·최근 이력·quality_selection |
| GET | `/template`, `/export` | 빈 양식, 현재 XLSX(v2) |
| POST | `/preview`, `/commit` | changes의 ships/voyages/cargo/assays 또는 업무형 entries/assay_entries. commit에는 revision 필요 |
| POST | `/excel/preview` | XLSX 바이트 검증, 변경 요약·파일 해시 |
| POST | `/excel/commit` | 같은 XLSX와 revision/file_digest/acknowledge_stale로 재검증 후 저장 |
| GET | `/inventory` | 화물별 수기 Pile 잔량과 대표 성상 |
| POST | `/inventory/receipts`, `/inventory/balance` | 실제 적치 배분과 사유가 있는 잔량 변경 |
| POST | `/inventory/reconcile` | 화물 전체 배분과 현재 잔량 정정, 원장 버전 확인 및 이력 보존 |
| POST | `/blend/recommend` | 선택 재고·목표 ARB 열량·AR 제한 기준 조합 계산 |

승인된 로그인, 허용 Origin, CSRF, 현재 X-Account-ID가 쓰기에 필요하다. 테스트는 임시 DB와 8097 격리 API를 사용하며 공용 ZGX에 쓰지 않는다.
