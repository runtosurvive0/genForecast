# 화면 분리와 AI 협업 체계

- 목표: 발전소·저탄장·선박 화면을 독립 폴더로 옮기고 팀원이 같은 Git 절차를 사용한다.
- 기준: SPEC.md, docs/DATA_DICTIONARY.md. 화면 동작·props·계산·상단바·사이드바를 유지한다.
- 작업 위치: 사용자가 동의한 현재 checkout의 refactor/split-features 브랜치. 별도 clone/worktree는 만들지 않는다.
- 기술: React / TypeScript / Vite / 기존 Node 및 Playwright 테스트.

## 작업 순서

1. 기존 28개 계산 테스트 확인.
2. ControlTower의 함수 본문을 유지한 채 화면별 모듈과 공통 표시 컴포넌트로 분리. 지도와 전용 CSS를 vessels로 이동.
3. AGENTS.md, CONTRIBUTING.md, Git 실습 안내와 AI 프롬프트, PR 템플릿 갱신.
4. 타입 검사·빌드·계산 및 브라우저 테스트, 전체 변경 리뷰.
5. 작업 브랜치 커밋·push·PR. 다른 팀원의 사람 리뷰 전 main에 머지하지 않는다.

## 검토 초점

- 화면 간 직접 import 없이 공통 모듈을 사용한다.
- CSS 분리 후 반응형·테마·오프라인 내보내기를 유지한다.
- 안내의 명령과 파일 경로가 실제 저장소와 맞고 사용자 변경을 보존한다.
- 문서상의 약속과 GitHub에서 실제 설정한 보호 규칙을 구분한다.

## 진행 기록

- 시작: main이 origin/main과 같고 작업 폴더가 깨끗함을 확인. 분리 전 계산 테스트 28/28 통과.
- Ruling: 동작을 추가하지 않는 추출이므로 구현을 복제하는 새 테스트 대신 기존 계산·UI 회귀 테스트를 사용한다. 개발자 지침의 불필요한 테스트 금지를 적용한다.
- 구현: 5개 화면 모듈, 공유 표현 컴포넌트, 기능별 CSS와 선박 지도 분리 완료.
- 검증: 화면 함수 본문 5개가 이전과 동일하며 CSS 규칙 101개의 선택자·선언·미디어 조건을 보존함.
- 검증: 계산 테스트 28/28, 브라우저 테스트 10/10, 타입 검사·빌드 성공. 문서 로컬 링크 확인 완료.
- 전달: 기존 승인대로 작업 브랜치 push와 PR까지 진행한다. 사람 리뷰와 실제 merge는 별도 단계다.
- 전체 변경 리뷰: Critical/Important 없음. SPEC §4와 역할·브랜치 설명의 혼동 가능성 1건을 문서에서 해소함. 원래 통합/발전소 소유권 기본을 유지하고 작업별 브랜치 수명을 명시함.
