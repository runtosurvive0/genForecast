# 선박 ETA 워크플로

## 한국행 후보 검색

`관심 선박 구성 → 실제 AIS 검색`에서 `한국행 후보 / 전체 / 목적지 미확인`을 선택한다.
AISstream 전 세계 수신은 유지하고 서버가 목적지 코드·이름으로 후보를 분류한다.
일반 20,000척과 별도로 후보 최대 1,000척을 목적지 관측 후 72시간 메모리에 보존한다.
분류 근거·목적지 수신 시각을 표시하며 확정 목적항이나 항차를 자동 생성하지 않는다.
창 높이·상단 탭·하단 완료 버튼을 고정하고, 각 탭 본문 하나만 스크롤한다.
AIS 표·관심 목록·목록 검색 안에 별도 세로 스크롤을 중첩하지 않는다.
라이트/다크·모바일 레이아웃을 지원한다. 자세한 API·별칭·보존 정책은
[VESSEL_API.md](../../../docs/VESSEL_API.md#한국행-후보-검색-2026-10-10)를 참고한다.

현재 단계는 **로컬 선박 추적 POC**다. AISstream/Digitraffic 실제 관측과 합성 표본을 구분한다.
실제 좌표·예상 해상 항로·서버 수집 항적과 관심 선박의 Open-Meteo 항로 예보를 지원한다. 기상 보정 ETA는 실제 예보와 미검증 감속 가정을 결합한 시연 모델이다. 공식 태풍 경보·로그인·자동 수급 반영은 연결하지 않았다.
실행·설치·저장 제한은 [선박 API 안내](../../../docs/VESSEL_API.md)를 참고한다.

## 화면에서 해볼 수 있는 것

선박 화면과 전용 대화상자의 일반 버튼·드롭다운은 조회 범위 컨트롤과 같은 34px 높이,
12px 글씨·7px 모서리를 사용한다. 상태 필터·탭은 전망 기간 버튼과 같은 11px 글씨와
4px 모서리의 선택형 컨트롤이다. 지도 확대·축소 같은 지도 내부 조작은 기존 소형 규격을 유지한다.

1. `관심 선박 구성`에서 선명·IMO·MMSI로 로컬 원장을 검색한다. `Aurora Bulk`는 출항 예정, `Meridian Coal`은 위치 미수신 예시다.
2. 식별자로 직접 등록하면 위치 연결 대기로 표시한다. 관심 목록은 브라우저에 저장되고 JSON 내보내기/가져오기를 지원한다.
3. 항차 연결/수정에서 목적 발전소, ETD, 거리·속도, 대기·하역 가정을 입력한다. 계획은 이 브라우저에만 저장되며 수급 원장은 바뀌지 않는다.
4. 실제 AIS 선박은 지도 위에서 목적항을 선택하면 기본 ETA와 계산 근거를 확인할 수 있다. 수동·합성 항차는 기존 입항 ETA와 등록 계획 대비 차이를 표시한다. 접안·하역 완료는 별도 가정이다.
   위치가 없는 선박을 선택해도 현재 필터 범위의 다른 선박은 지도에 남는다. 선택한 선박의 위치 미수신 안내를 따로 표시하며 다른 배를 대신 선택하지 않는다. 필터 범위 전체에 지도 표시 가능한 선박이 없을 때만 지도에 빈 상태를 표시한다.
5. 기존 항해 표본에서 `기상 표본 표시`를 켜면 지도 구간에 파고와 바람 예시가 나타난다. KST 시간축과 기상 실패 시연으로 자료 없음 상태를 확인한다.
6. 실제 관심 선박은 `확인한 목적항`을 지정하면 백그라운드 순차 조회로 기상 상태가 표시된다. `항로 통과 예보`에서 향후 최대 72시간의 파고·바람·돌풍을 비교하고 지도 표시를 켠다. 합성 선박의 표본 패널과 분리한다.
7. `도착 전망`에서 기본 ETA와 기상 보정 ETA·추가 지연·보정 구간을 비교한다. `보정 가정 및 구간별 영향`을 펼치면 감속 민감도(0~1.5배)를 조절할 수 있다. 선택 선박·목적항 변경 시 기본 1배로 돌아가며 서버나 항차 원장에 저장하지 않는다.

## 지도 선박 아이콘

- 이동 중에는 뾰족한 선체가 AIS COG(대지 진행 방향)를 가리킨다. 실제 선수 방향(Heading)으로 표시하지 않는다.
- COG 미수신·범위 밖, SOG 미수신·0.5kn 미만, AIS 묘박(1)·계류(5)는 방향성 없는 원형 점으로 표시한다.
- 실제 AIS와 합성 표본 모두 해당 관측의 COG/SOG를 사용한다. 목적항·예상 항로로 방향을 만들어내지 않는다.
- 지구본·평면·오프라인 지도 투영에서 현재 좌표의 진행 벡터를 화면 각도로 변환한다. 날짜변경선에서 방향이 뒤집히지 않게 처리한다.
- 선체는 확대해도 일정한 크기이며 선택 시 보라색과 얇은 외곽선으로 구분한다. 선박명은 수평 유지, 키보드 포커스와 터치 영역은 별도다.
- 구현: `vessel-symbol.ts`의 방향 계산·공통 도형, `OfflineVesselSymbol.tsx`, 두 지도 렌더러 및 `vessel-map.css`. 새 의존성이나 서버 변경은 없다.

## 지도 경로와 실제 위치의 연결

- 예상 항로망 시작점과 실제 좌표가 다른 경우 가는 점 연결선을 별도로 그린다. 연결선은 항해 가능한 경로가 아니며, 항로 거리·ETA 계산에 더하지 않는다.
- AIS가 갱신되면 연결선 시작점도 즉시 같은 좌표로 갱신한다. 경로 캐시를 위해 선박 좌표를 옮기거나 이전 위치에 고정하지 않는다.
- 저장된 항적 뒤에 더 최신의 실제 AIS 관측이 있으면 화면에서 이어 표시한다. 6시간 초과 공백·비정상 점프·역순 시각은 연결하지 않는다. DB 기록 자체는 수정하지 않는다.

## 데이터 경계

- `src/domain/vessel-workflow.ts`: 선박과 항차를 분리한 새 로컬 계약, ETA 계산, 저장/가져오기 검증. 기존 공급 계산을 수정하지 않는다.
- `src/data/vessel-workflow.ts`: 기존 4척에 연결한 별도 합성 어댑터와 추가 표본. 신규 원장 IDs는 기존 항차 IDs와 구분한다.
- `VesselWorkspace.tsx`: 신규 화면. `App.tsx`의 import 한 줄로 연결했다. 이전 `VesselTracking.tsx`는 보존했다.
- `VesselMap.tsx`: 선택적 기상 포인트를 받는다. 워크스페이스는 `showVesselPanel={false}`로 지도 내부 목록·상세를 생략하고 범례만 남긴다. 선박 선택은 관심 목록과 지도 마커가 공유하며, ETA 계산 근거와 항차 정보는 도착 전망에서 확인한다. 독립 지도는 기존 목록·상세를 기본 제공한다. 임의 선박이나 변경된 목적지에는 기존 예시 항로를 재사용하지 않는다.
- `useVesselWorkspace.ts`: `genforecast.vessel-workspace.v1` 로컬 저장. 관심 해제는 원장과 항차를 삭제하지 않는다. 가져오기는 병합하며 현재 항차 수정값을 우선한다.

기본 항해 ETA는 마지막 관측 시각 + 잔여거리 / SOG다. 단일 관측 기반이며 속도 추세·선박별 실측 성능 모델은 아직 없다. 별도 시연용 기상 보정은 아래 기준을 사용한다. 출항 전에는 등록 항차의 ETD와 계획 속도를 사용한다. 정지/취소/필수 입력 누락은 미확정이다. 새 관측 없이 조회 시각만 바뀌어도 기본 ETA는 밀리지 않는다.

### 실제 AIS 기본 ETA

- `vessel-basic-eta.ts`에서 목적항이 확인된 예상 항로와 실제 AIS 관측으로 계산한다. 항차 등록 없이 관심 목록·도착 전망에 표시하며 **기상 미반영**을 명시한다.
- 항로 캐시를 재사용할 때는 현재 좌표를 경로에 투영해 남은 거리 비율을 계산한다. 위치 연결선·항만 진입·접안 대기는 포함하지 않으므로 항로망 끝점 기준 참고값이다.
- 계산 보류 조건: 위치·시각 오류, 미래 관측, 1시간 초과 관측, 속도 미수신·0.5kn 미만, 묘박·계류·좌초, 출항 전·입항·취소·정지로 등록된 항차. 이미 지난 예상 시각도 재확인을 요청한다.
- POC 검토 기준으로 화물선·탱커(AIS 유형 70~89)는 40kn 초과, 그 외는 60kn 초과 보고 속도를 보류한다. 이는 AIS 규격의 유효성 판정이 아니다.
- 6시간 초과 항로, 항로망 시작 오차 5nm 초과·목적항 오차 20nm 초과, 현재 위치의 경로 이탈 5nm 초과는 갱신·확인이 필요하다. 선택 선박의 이전 수집 위치와 6시간 이내 비교 시 `1nm + 경과시간 × 60kn`보다 큰 이동도 보류한다.
- 위 기준은 오류 가능성을 줄이는 제한이며 모든 육상 좌표·잘못된 AIS를 검출하지 못한다. 별도의 해수면 판정과 실제 운영 검증은 미구현이다.
- 목적항 변경 시 이전 목적항의 ETA를 재사용하지 않는다. 동일 목적항 갱신 실패 시 유효한 이전 계산을 유지하면서 오류를 표시한다. 등록 화물·계획 ETA·접안·하역 가정과 재고 원장은 수정하지 않는다.
- 선택한 선박의 항로만 요청하며, 같은 화면에서 계산했던 다른 선박은 캐시가 유효할 때 목록 ETA를 유지한다. 새 API·키·의존성을 추가하지 않는다.

합성 선박의 기상 시간축은 **선택 시각의 합성 표본**이다. 예시 기상은 48시간까지만 제공한다. 실제 관심 선박은 예상 항로 통과 시각별 Open-Meteo 예보를 별도 표시한다. 두 경우 모두 범위 밖·연결 실패를 안전 상태로 표시하지 않으며 실제 태풍 반경이나 경보처럼 보이는 도형을 만들지 않는다.

Thinking Orbs는 파일 읽기와 전체 지도 소스·스타일의 로딩 및 화면 반영에 사용한다. 250ms 미만의 작업은 표시하지 않으며, 즉시 끝나는 로컬 검색/계산에 인위적 지연을 넣지 않는다.

실제 AIS 검색 탭에서는 탭 줄 오른쪽에 수신 상태와 마지막 메시지 시각을 표시한다.
좁은 화면에서는 탭 바로 아래 오른쪽에 배치한다.
AISstream 연결·첫 메시지 대기·재연결과 최근 수신 중에는 20px Thinking Orb를 유지한다.
마지막 메시지로부터 60초가 지나면 수신 지연으로 표시하고 Orb를 제거한다. 이 기준은
스트림 활동 표시용이며 개별 선박의 LIVE/RECENT 판정과는 다르다. 조회 오류에도 Orb를
제거하고 이전 목록을 보존한다. Digitraffic의 완료된 단발 조회에는 계속 회전하지 않는다.
탭 사이 헤더 공간을 유지하고, 동작 줄이기 설정에서는 Orb를 정지 프레임으로 표시한다.

### 시연용 기상 보정 ETA

`vessel-weather-eta.ts`는 API 호출 없이 이미 받은 예보로 계산한다. `VesselWeatherEta.tsx`는 기본 ETA 바로 아래에 비교값을 표시한다. 관심 목록의 날짜는 계속 기본 ETA다. 신규 키·의존성·DB는 없다. 응답에 계산 기준 속도 `speedKn`이 추가되어 기존 Python 서버는 한 번 재시작해야 한다.

- 미검증 가정: 파고 1.5m 초과분에 4%p/m, 풍속 15kn 초과분에 0.2%p/kn. 방향 가중치는 `0.5 + 0.5 × max(0, cos(유입 방향 − 항로 방향))`. 합계에 민감도를 곱하고 30%로 제한한다.
- 구간 양 끝의 부담을 평균한다. 현재 SOG에 기상이 이미 포함되어 있으므로 현재 지점 부담을 차감해 `r = max(0, (구간 부담 − 현재 부담) / (1 − 현재 부담))`를 구한다. 추가 시간은 `기본 구간 시간 × r / (1 − r)`. 현재보다 나아지는 기상에 가속을 임의 부여하지 않는다.
- AIS·예보의 선박/목적항 일치, 기본 ETA 유효, 예보 관측 기준 15분 이내, 위치 차이 5nm 이내가 필요하다. 각 공급자 원자료는 3시간 미만의 fresh 상태이며 유효 예보 시각이 기본 통과 시각과 30분 이내여야 한다.
- 예보 계산 당시 `speedKn`과 최신 SOG 차이가 `max(0.1kn, 기준 속도의 2%)`를 넘으면 이전 통과 시각을 적용하지 않는다. 기상 갱신 또는 정기 조회로 새 예보를 받은 뒤 보정한다. 이는 시연용 일치 허용 범위이며 실제 ETA 오차 보장이 아니다. 이전 서버의 속도 메타데이터 없는 응답은 지도 표시만 허용한다.
- 첫 지점의 기준 기상이 없으면 보류한다. 누락·stale·방향 미수신·동일 좌표 구간과 예보 범위 밖은 미보정 시간으로 남긴다. 파고 8m, 풍속 50kn, 돌풍 65kn 초과도 시연 범위 밖이며 안전 기준이 아니다. 유효 구간이 없으면 날짜를 표시하지 않는다.
- 일부만 계산되면 **부분 기상 보정 ETA**와 보정/미보정 시간을 표시한다. 미보정 구간은 기본 SOG 유지 가정이며 무풍·안전 또는 지연 상한을 뜻하지 않는다. 이미 지난 구간은 추가 지연에서 제외한다.
- 기본 통과 시각의 예보를 고정한 **1회 감도 분석**이다. 지연 후 시각의 기상 재조회·반복 적분, 선체·흘수·적재·기관 출력·해류·우회·항만 대기는 미구현이다. 돌풍은 범위 검사에만 사용하고 파주기는 수치에 사용하지 않는다. 발표용 비교이며 선박별 검증된 ETA가 아니다.
- 참고: [선박 운항 자료와 성능 예측 연구](https://arxiv.org/abs/2212.13061), [Open-Meteo Marine 변수](https://open-meteo.com/en/docs/marine-weather-api). 위 감속 계수는 이 자료에서 인용한 값이 아니라 프로젝트 시연 가정이다.

## 선박 추적 작업 화면

- 왼쪽 260px 열에 상태 필터와 관심 목록, 오른쪽 열에 선택 선박·마지막 관측·항로 조작·지도를 배치한다. 상단바와 사이드바는 유지한다.
- 관심 목록은 세로 구분선 대신 테마에 맞는 옅은 배경으로 구분하고 선택 타일은 강조 배경을 사용한다. 예상 해상거리 요약과 도착 전망 사이의 중복 구분선은 없앤다.
- 관심 타일에 마지막 위치 관측의 SOG를 소수점 한 자리 kn로 표시한다. 0kn과 미수신은 구분하고, 합성 선박은 `표본 속도`로 표시한다. 관측 시각·최신성 배지를 함께 확인한다.
- `VesselMap`의 `embedded` 모드는 중복 카드 제목을 생략한다. 출처·선택 선박의 위치 미수신 안내·범례는 유지한다.
- 지도 아래에 예상 해상거리·수집 기록과 도착 전망·계산 근거를 배치한다. 항로 계산 기준과 관측·항차 상세는 펼쳐 확인한다. 오류와 위치 경고는 접지 않는다.
- ETA가 없으면 날짜나 KST를 붙이지 않고 `ETA 계산 전` 또는 `ETA 계산 보류`와 필요한 입력·보류 사유를 안내한다. 저장 계약은 변경하지 않는다.
- 가져오기·내보내기는 상단 더보기 메뉴로 이동한다. 900px 이하에서는 목록을 접고 펼칠 수 있고, 650px 이하에서는 상세를 한 열로 배치한다.

# 항로 기상 레이어 (2026-10-10)

- 실제 관심 선박의 목적항과 통과 예보를 준비한 뒤 지도 도구의 **기상**을 켠다. 파고·바람·시정을 전환하고 지도 하단 통과 시각을 선택한다. 지점 표식 클릭도 동일한 선택을 바꾼다. 지도 카메라를 재설정하지 않는다.
- 각 표식은 그 지점의 통과 시각 예보다. 전체 해역의 동일 시각 기상장/안개 면적 예보가 아니다. 시정은 `visibilityM`(m), 미제공은 null/구서버 undefined이며 0은 유효하다. 3m/25kn/시정 1km 미만은 시연 강조 기준이며 법규·선박 안전 한계가 아니다.
- 태풍 데이터는 GDACS 최근 4일 최대 100개 재난 피드에서 현재 열대저기압 최대 16개를 읽고, 원기관(NOAA/JTWC 등)의 최신 advisory timeline을 정규화한다. 전 세계 완전성이나 항행 경보를 보장하지 않는다.
- 최근 24시간 이내 기준 자료 중 통과 표본 시각 ±3h에 예보가 있고 300nm 또는 최대 34kt 반경+100nm 이내인 태풍을 후보로 표시한다. 검색 범위는 위험 원으로 그리지 않는다. 반경과 중심 시각은 원자료 그대로 표시하고 시각 간 반경을 보간하지 않는다. 표본 사이의 영향은 탐지하지 못할 수 있다.
- 점선은 최신 기준 중심 예상 경로, 주황 음영은 제공된 NE/SE/SW/NW 34kt 최대 반경을 지구 구면상 부채꼴로 변환한 영역이다. 경로 불확실성 cone 또는 균일한 풍속장이 아니다. 미제공 방향은 만들지 않는다. 날짜변경선에서는 경도를 연속화한다.
- 태풍 조회는 서버 공유 30분 캐시/동시 요청 병합/최대 4개 병렬이다. 실패 재시도 간격 60초, 이전 캐시는 최대 6h까지 명시적으로 stale 표시하고 이후 숨긴다. 클라이언트는 레이어를 켠 실제 관심 선박에 통과 표본이 있을 때만 조회한다. 브라우저 새로고침/줌/시간 슬라이더마다 외부 API를 다시 호출하지 않는다.
- 시정·태풍은 기존 기상 보정 ETA에 별도 지연을 더하지 않는다. 입항 통제·도선·재고·항차 일정은 변경하지 않는다. 실제 API 키 추가 발급은 불필요하며 백엔드 재시작이 필요하다.
